Scenario Briefing

Contoso Healthcare has onboarded a new clinical development team (4 members) who need access to an Azure subscription hosting a patient records application. Your job: provision their identities, assign least-privilege access, enforce security policies, enable threat protection, and set up secure remote access to a backend VM.

You'll work through this as if you're the Security Administrator for the tenant.

Step 2 of 6

Assign RBAC Role

The ClinicalDev-Team group needs access to the "PatientRecords-RG" resource group. They need to deploy and manage application resources but should not be able to manage access for others. Which role?

PatientRecords-RG > Access control (IAM) > Add role assignment

Owner

Full access including the ability to assign roles to others.

Contributor

Create and manage all resource types. Cannot grant access to others.

Reader

View all resources but cannot make changes.

User Access Administrator

Manage user access to Azure resources. No resource management.

Step 4 of 6

Troubleshoot Access Failure

After deploying the CA policy, a team member (graeme@mcacloud.uk) reports they can sign in but see "You don't have access to this" with error 530035. The troubleshooting details show Device state: Unregistered. What's the most likely cause?

Sign-in logs > graeme@mcacloud.uk > Error 530035
Error Code: 530035
Failure reason: Access policy does not allow token issuance
Authentication: Success
Conditional Access: Failure
Device state: Unregistered
MFA satisfied: Yes

MFA registration is incomplete

The user hasn't finished setting up their authenticator app.

The CA policy requires a compliant device but this device is unregistered

The device isn't Entra joined or registered, so the compliant device grant control fails.

The user's account is disabled

The account exists but has been blocked from sign-in.

The user isn't licensed for Azure AD P1

Conditional Access requires at least Azure AD P1/P2 licensing.

Step 5 of 6

Enable Microsoft Defender for Cloud

The subscription needs threat protection. You're enabling Defender for Cloud. Which plan configuration is appropriate for a subscription running VMs with a patient records web app?

Defender for Cloud > Environment settings > PatientRecords-Sub

Enable Foundational CSPM only (free tier)

Secure score and basic recommendations. No workload protection or advanced threat detection.

Enable Defender for Servers (Plan 2) and Defender for App Service

Workload protection for VMs (file integrity, JIT, adaptive controls) and web app threat detection.

Enable all Defender plans across every resource type

Maximum coverage: Servers, App Service, SQL, Storage, Key Vault, DNS, Containers, etc.

Enable Defender for Storage and Defender for Key Vault only

Protects data at rest and secrets management. No server or app protection.

Step 6 of 6

Deploy Azure Bastion for Secure Access

The backend VM has no public IP. The team needs RDP/SSH access for maintenance. You're deploying Azure Bastion. What's the correct network configuration?

PatientRecords-VNet > Subnets > Deploy Bastion

Create subnet "BastionSubnet" with /27 prefix, deploy Bastion Standard SKU

Dedicated subnet with correct minimum size. Standard SKU supports native client and IP-based connections.

Create subnet "AzureBastionSubnet" with /26 prefix, deploy Bastion Standard SKU

Correctly named dedicated subnet with recommended size. Standard SKU for full features.

Create subnet "AzureBastionSubnet" with /28 prefix, deploy Bastion Basic SKU

Correctly named subnet but smaller prefix. Basic SKU with limited features.

Deploy Bastion into the existing default subnet, assign a public IP to the VM

No dedicated subnet. The VM gets a public IP for direct access alongside Bastion.
