Engagement Scenario

With Domain Admin access established throughout the engagement, the final technical task is to document the patch posture of the environment. A poorly patched DC is a standalone finding with high severity - especially if any missing patches map to publicly known exploits. You will enumerate installed patches via three methods, check the WSUS configuration, and produce a patch findings summary ready for the report.

Learning Objectives

OS Version and Patch Date - First Look

systeminfo / wmic

Start with systeminfo to get OS version, build number, and the last patch date in one command. On a shell session on the target:

# Full system and patch summary
systeminfo

Host Name:                 SYNTEX-DC01
OS Name:                   Microsoft Windows Server 2016 Standard
OS Version:                10.0.14393 Build 14393
System Type:               x64-based PC
Hotfix(s):                 6 Hotfix(s) Installed.
                           [01]: KB4537764
                           [02]: KB4540673
                           [03]: KB4565503
                           [04]: KB4568831
                           [05]: KB4570720
                           [06]: KB4571735

# Parse just the hotfix list and OS version for the report
systeminfo | findstr /i "hotfix\|os version\|build"

Calculate days since last patch: Windows Server 2016 with 6 hotfixes installed and build 14393.3442 (KB4571735 is from August 2020) means this DC has not been patched in over 4 years. This is a critical finding:

Full Patch Enumeration with wmic qfe and Get-HotFix

PowerShell

Use both wmic and PowerShell to get a complete hotfix list with install dates. Cross-referencing both tools catches edge cases where one method misses a patch:

# wmic qfe - outputs all installed hotfixes with dates and installer
wmic qfe get HotFixID,InstalledBy,InstalledOn,Description /format:csv > C:\Windows\Temp\patches.csv

# PowerShell Get-HotFix - cleaner output, sortable by date
Get-HotFix | Select-Object HotFixID, Description, InstalledBy, InstalledOn | Sort-Object InstalledOn -Descending

Testers use all three because wmic qfe sometimes misses driver updates that Get-HotFix catches.

WSUS Configuration Audit

Registry

WSUS (Windows Server Update Services) is the Microsoft patch management solution. When WSUS is misconfigured or a client points to a rogue WSUS server, patches are never applied. Check the WSUS registry settings on the DC:

# Check Windows Update / WSUS registry configuration
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate" /s

HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate
    WUServer    REG_SZ    http://syntex-wsus.syntex.local:8530
    WUStatusServer    REG_SZ    http://syntex-wsus.syntex.local:8530
    TargetGroupEnabled    REG_DWORD    0x1
    TargetGroup    REG_SZ    DomainControllers

HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU
    UseWUServer    REG_DWORD    0x1
    NoAutoUpdate    REG_DWORD    0x1
    AUOptions    REG_DWORD    0x2

# AUOptions values:
# 2 = Notify before download (manual approval required)
# 3 = Auto download, notify to install
# 4 = Auto download and install (recommended)
# NoAutoUpdate = 1 means automatic updates are DISABLED
# FINDING: NoAutoUpdate=1 + AUOptions=2 = patches require manual admin approval
# This is why the DC hasn't been patched since August 2020

Verify if the WSUS server is actually reachable and check for WSUS-related vulnerabilities:

# Test connectivity to WSUS server
Test-NetConnection -ComputerName syntex-wsus.syntex.local -Port 8530

ComputerName     : syntex-wsus.syntex.local
RemoteAddress    : 192.168.1.20
RemotePort       : 8530
InterfaceAlias   : Ethernet0
SourceAddress    : 192.168.1.10
TcpTestSucceeded : False

# WSUS server unreachable - DC cannot receive updates even if approved

# Also check: is WSUS running over HTTP (not HTTPS)?
# The WUServer value shows http:// (not https://) - this is exploitable
# via WSUS HTTP interception attacks (WSUS-Attack / WSUSpendu)
# WSUS over HTTP = attacker on the same network can MITM the update stream
# and push malicious "updates" to the target. This is a HIGH finding.
★
CREST CPSA Exam Point: WSUS running over HTTP (port 8530) instead of HTTPS (port 8531) is a HIGH finding. An attacker with network access can intercept the update stream and deliver a malicious "patch" that executes as SYSTEM. WSUS should always use HTTPS with a valid certificate. Also look for: auto-approval rules that approve all updates without testing, non-SSL connections to Windows Update, and GPO settings that disable automatic updates (NoAutoUpdate=1).

Mapping Missing Patches to CVEs

Reporting Evidence

Identify the highest-impact CVEs that would be present on an unpatched Windows Server 2016 build 14393.3930 (last patched August 2020). These become your critical patch findings:

Critical - PrintNightmare

CVE-2021-34527. Remote code execution via Windows Print Spooler. CVSS 8.8. Fixed in out-of-band patch June 2021. Exploitable with Impacket or public PoC. This DC is vulnerable.

Critical - Zerologon

CVE-2020-1472. Authentication bypass against DC's Netlogon service. CVSS 10.0. Fixed in August 2020 patch - KB4571694. Check if this specific KB is present before claiming.

High - PetitPotam

CVE-2021-36942. NTLM relay via MS-EFSRPC. Fixed in August 2021 cumulative update. Allows relay of DC machine account to AD CS for domain takeover if ADCS present.

High - MSHTML RCE

CVE-2021-40444. Remote code execution via MSHTML component. CVSS 8.8. Fixed in September 2021 cumulative update. Exploited in the wild via malicious Office documents.

Writing the Patch Findings for the Report

Report Writing

A patch finding in a CREST-standard report requires: title, risk rating, CVSS score, affected component, evidence, business impact, and remediation. Here is a complete example for the patch posture finding:

## Finding: Critical Unpatched Windows Domain Controller
## Risk: HIGH | CVSS: 8.8 (network attack vector)

Title:     Unpatched Windows Server 2016 Domain Controller
Ref:       SYNTEX-PATCH-001
Severity:  HIGH
CVSS:      8.8 (AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H)
Host:      SYNTEX-DC01 (192.168.1.10)

Summary:
SYNTEX-DC01 has not received security updates since August 2020,
leaving it exposed to over 1,400 security patches including multiple
publicly exploited critical vulnerabilities.

Evidence:
  Last hotfix installed: KB4571735 (InstalledOn: 8/11/2020)
  OS Build: 10.0.14393.3930
  Current latest build: 14393.7876+ (as of engagement date)

  wmic qfe output (excerpt):
  HotFixID   InstalledOn
  KB4571735  8/11/2020   <-- most recent

Notable Missing Patches:
  CVE-2021-34527 (PrintNightmare) - CVSS 8.8 - RCE via Print Spooler
  CVE-2020-1472  (Zerologon)      - CVSS 10.0 - Auth bypass on DC Netlogon
  CVE-2021-36942 (PetitPotam)     - CVSS 7.5 - NTLM relay via EFS

Root Cause:
  NoAutoUpdate=1 in HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU
  WSUS server (syntex-wsus.syntex.local:8530) is unreachable
  WSUS configured over HTTP (not HTTPS) - susceptible to interception attack

Business Impact:
  Any authenticated domain user can exploit PrintNightmare to achieve SYSTEM
  on this Domain Controller and compromise the entire syntex.local domain.
  This represents a complete loss of confidentiality, integrity, and availability
  of all domain-joined systems and cardholder data in scope for PCI DSS v4.0.

Remediation:
  1. Apply all outstanding Windows cumulative updates immediately
  2. Configure WSUS over HTTPS (port 8531) with a valid certificate
  3. Set AUOptions=4 and NoAutoUpdate=0 to enable automatic updates
  4. Verify WSUS server connectivity and approval workflows
  5. Implement a patch management process with monthly patching SLA
★
CREST CPSA Exam Point: Patch findings must be evidence-based. Never claim a CVE is present without verifying the patch KB is missing. Watson.exe automates this check. Always include the specific build number, the last-patched date, and at least one CVE with its CVSS score in the finding. The business impact must explain WHY this matters to the client (domain compromise, PCI DSS breach), not just that the patch is missing.

Knowledge Check

Q1. Which command gives you installed hotfixes sorted by install date, most recent first?

A. wmic qfe list full
B. Get-HotFix | Sort-Object InstalledOn -Descending
C. systeminfo | findstr "Hotfix"
D. reg query HKLM\SOFTWARE\Microsoft\Updates

Q2. The WSUS registry key shows WUServer = http://wsus.corp.local:8530 (not HTTPS). What is the security risk?

WSUS over HTTP (port 8530) means the update stream is unencrypted. An attacker with network access (e.g. from the same VLAN or via ARP spoofing) can intercept the traffic between the DC and WSUS server and inject a malicious "update" package. Because updates are applied as SYSTEM, this gives the attacker full SYSTEM code execution on every machine that polls this WSUS server. The fix is to configure WSUS over HTTPS (port 8531) with a valid certificate so the update stream cannot be tampered with.

Q3. PrintNightmare (CVE-2021-34527) allows an authenticated domain user to achieve what level of access on an unpatched Domain Controller?

A. Domain User - it only adds a local printer
B. Local Administrator on the workstation running the exploit
C. SYSTEM on the DC - via the Print Spooler service running as SYSTEM
D. Domain Admin only if combined with a second exploit

Key Takeaways

  • Use all three patch enumeration methods: systeminfo, wmic qfe, and Get-HotFix - they complement each other
  • Always check the WSUS configuration - NoAutoUpdate and AUOptions reveal WHY patches are missing
  • WSUS over HTTP is a HIGH finding - the update stream can be intercepted and weaponised
  • Map missing patches to CVEs with Watson.exe - never claim a CVE without verifying the KB is absent
  • Include build number, last patch date, specific CVEs, and business impact in every patch finding
  • A DC not patched since 2020 is a standalone critical engagement finding regardless of other findings
