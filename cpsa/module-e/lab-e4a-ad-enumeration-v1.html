Lab E4-A: Active Directory Enumeration - LDAP and BloodHound

Module E Active Directory CREST CPSA Difficulty: Intermediate Estimated time: 60 min

Engagement Scenario

You have a valid domain credential (svc-backup / Password1) from the SMB share enumeration. Use this to perform comprehensive Active Directory enumeration via LDAP and BloodHound. The goal is to identify all high-value targets, Kerberoastable accounts, and attack paths to Domain Admin before running any further exploits.

Learning Objectives

  • Query Active Directory via LDAP using ldapsearch and ldapdomaindump
  • Identify Kerberoastable and AS-REP Roastable accounts from LDAP attributes
  • Run SharpHound to collect BloodHound graph data
  • Interpret BloodHound attack paths to identify the shortest route to Domain Admin

LDAP Enumeration with ldapsearch

ldapsearch

LDAP is the query interface to Active Directory. Any authenticated domain user can query it. Start by confirming the base DN and domain structure:

# Test anonymous LDAP bind first
ldapsearch -H ldap://<DC01-IP> -x -s base namingContexts

# Authenticated enumeration - all users
ldapsearch -H ldap://<DC01-IP> -x -D "svc-backup@syntex.local" -w Password1 \
  -b "DC=syntex,DC=local" "(objectClass=user)" sAMAccountName description

dn: CN=Administrator,CN=Users,DC=syntex,DC=local
sAMAccountName: Administrator

dn: CN=jsmith,CN=Users,DC=syntex,DC=local
sAMAccountName: jsmith
description: User account for J. Smith - temp password Welcome1

dn: CN=svc-backup,CN=Users,DC=syntex,DC=local
sAMAccountName: svc-backup

Note the description field on jsmith - administrators frequently store passwords there. This is always worth querying.

Key LDAP queries for penetration testing. Run each one:

TargetFilterWhy It Matters
Kerberoastable accounts(servicePrincipalName=*)Accounts with SPNs - can request TGS tickets for offline cracking
AS-REP Roastable(userAccountControl:1.2.840.113556.1.4.803:=4194304)Pre-auth disabled - hash requestable without credentials
Domain Admins(memberOf=CN=Domain Admins,...)Priority targets for session hunting
Disabled accounts(userAccountControl:1.2.840.113556.1.4.803:=2)Often still have permissions configured
Password in description(description=*pass*)Administrators store creds in descriptions

Comprehensive Dump with ldapdomaindump

ldapdomaindump

ldapdomaindump performs a full AD dump and outputs structured HTML and JSON files for offline analysis. It is faster than running individual ldapsearch queries:

# Full AD dump to a local directory
mkdir syntex_ldap
ldapdomaindump -u "syntex.local\svc-backup" -p Password1 <DC01-IP> -o syntex_ldap/

# Files generated:
syntex_ldap/
  domain_users.html       - All users with attributes
  domain_groups.html      - All groups and members
  domain_computers.html   - All computer objects
  domain_policy.html      - Domain password policy
  domain_trusts.html      - Domain trust relationships
  domain_users.json       - Machine-readable user data

Check the password policy - this determines whether password spraying is safe without triggering lockouts:

# View the domain password policy
crackmapexec smb <DC01-IP> -u svc-backup -p Password1 --pass-pol

Minimum password length: 6
Password complexity: Disabled
Lockout threshold: 0 (no lockout)
Lockout duration: None
# No lockout threshold - password spraying is safe in this environment
★
CREST CPSA Exam Point: Always check the password policy before spraying. Lockout threshold of 0 means no lockout (safe). A threshold of 3-5 means you must spray slowly with gaps between attempts to avoid locking out accounts. Locking out accounts is a significant negative finding on any engagement.

BloodHound Collection with SharpHound

SharpHound + BloodHound

BloodHound uses graph theory to map AD relationships and calculate attack paths. SharpHound is the data collector - run it on the target domain, then import the output into BloodHound for analysis.

Option 1: Run SharpHound directly from your Evil-WinRM shell (requires upload to target):

# Upload SharpHound to the target via Evil-WinRM
*Evil-WinRM* PS C:\Users\svc-backup> upload SharpHound.exe

# Run SharpHound - collect all data
*Evil-WinRM* PS C:\Users\svc-backup> .\SharpHound.exe -c All

[*] Collection Methods: Group, LocalAdmin, Session, Trusts, ACL, Container, RDP, ObjectProps, DCOM, SPNTargets, PSRemote
[*] Completed 183 objects
[*] Writing output to 20241021132155_BloodHound.zip

# Download the zip back to Kali
*Evil-WinRM* PS C:\Users\svc-backup> download 20241021132155_BloodHound.zip

Option 2: Run the Python BloodHound collector from Kali (no binary needed on target):

# bloodhound-python - runs from Kali, queries DC over LDAP/SMB
bloodhound-python -u svc-backup -p Password1 -d syntex.local -ns <DC01-IP> -c All

[*] Found AD domain: syntex.local
[*] Getting TGT for user
[*] Connecting to LDAP server: SYNTEX-DC01.syntex.local
[*] Found 8 domains
[*] Found 4 users
[*] Found 52 groups
[*] Enumeration done in 00h:00m:42s

Start BloodHound and import the data:

# Start Neo4j (required database backend)
sudo neo4j start

# Start BloodHound GUI
bloodhound &

# In BloodHound GUI:
# 1. Login: neo4j / neo4j (change on first login)
# 2. Click Upload Data (top right)
# 3. Select the BloodHound .zip file
# 4. Wait for import to complete
ℹ
Key BloodHound Queries to run after import: Find Shortest Paths to Domain Admins, Find all Domain Admin accounts, List all Kerberoastable Accounts, Find Principals with DCSync Rights, Find Computers where Domain Users are Local Admin.

Interpreting BloodHound Attack Paths

BloodHound Analysis

In the BloodHound search bar, run pre-built queries from the Analysis tab. For the Syntex domain, you should find:

# Query 1: Shortest path from svc-backup to Domain Admins
# BloodHound GUI: Analysis > Find Shortest Paths to Domain Admins
# Expected result: svc-backup -> [GenericWrite on jsmith?] or via Kerberoasting path

# Query 2: All Kerberoastable accounts
# BloodHound GUI: Analysis > List all Kerberoastable Accounts
svc-backup (servicePrincipalName set, not DA)

BloodHound uses edge types to describe relationships. Know these for CPSA:

# Critical BloodHound edges:
MemberOf        - User is a member of this group
AdminTo         - User has local admin rights on this computer
HasSession      - A privileged user has an active session on this computer
CanRDP          - User can RDP to this host
GenericWrite    - User can write to an AD object (ACL abuse)
WriteDACL       - User can modify an object's DACL
DCSync          - User has replication rights (can dump all hashes)
★
CREST CPSA Exam Point: BloodHound's "Shortest Paths to Domain Admins" is the first query you run on every engagement. Without it you move blind. The path BloodHound shows is pre-calculated from the collected data - it shows exactly which hops are needed to reach DA, in order. Follow that path.

Knowledge Check

Q1. You find a user with a description field that reads "Temp password: Summer2024!". What type of finding is this, and what severity?

This is a credential exposure finding - HIGH severity. LDAP description fields are readable by any authenticated domain user. Storing passwords in user descriptions is equivalent to leaving them in a publicly accessible text file. The credential should be tested against all network services and documented as a critical misconfiguration.

Q2. BloodHound shows a HasSession edge from "Administrator" to "WORKSTATION01". What does this mean for your attack?

A. Administrator is installed on WORKSTATION01
B. Administrator has an active logon session on WORKSTATION01 - compromise it and dump LSASS to get the DA hash
C. WORKSTATION01 is in the Administrators group
D. Administrator has remote desktop access to WORKSTATION01

Q3. The domain password policy shows Lockout threshold: 0. What does this mean for password spraying?

A. No spraying is possible - accounts are immediately locked
B. Spraying is safe - there is no lockout policy configured
C. You can only spray once per account
D. Accounts lock after zero attempts - do not spray

Key Takeaways

  • LDAP exposes the entire AD directory to any authenticated domain user - no special rights needed
  • Always check the Description field on user objects - administrators frequently store passwords there
  • ldapdomaindump gives you structured HTML output for all AD objects in a single command
  • BloodHound "Shortest Paths to Domain Admins" is always your first query - it defines the attack plan
  • HasSession edges are the most valuable BloodHound finding - they show where you can dump DA credentials
