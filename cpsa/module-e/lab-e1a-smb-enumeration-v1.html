Lab E1-A: SMB Enumeration

Module E Windows CREST CPSA Syntex Solutions Ltd Difficulty: Intermediate Estimated time: 45 min

Engagement Scenario

You are conducting an internal network penetration test against Syntex Solutions Ltd, a UK-based fintech firm regulated under PCI DSS v4.0. Your Kali Linux attack host has been placed on the internal network segment. The Windows Domain Controller (SYNTEX-DC01) is in scope. Your first task is to enumerate the SMB service to identify shares, sessions, users, and misconfigurations that will underpin the rest of the assessment.

Learning Objectives

  • Identify SMB version and signing status using Nmap
  • Enumerate null sessions, shares, and users with enum4linux-ng
  • Access readable SMB shares and extract credential artefacts
  • Map SMB findings to CREST CPSA examination topics

1

SMB Version and Signing Detection

Nmap NSE

Start with an Nmap scan targeting SMB-related ports. The smb-security-mode and smb2-security-mode scripts reveal whether message signing is enforced - a critical finding that determines whether relay attacks are viable.

# SMB version and security mode detection
nmap -p 445,139 --script smb-security-mode,smb2-security-mode,smb-protocols -sV <DC01-IP>

Also run the full SMB enumeration script set to identify the OS version, domain name, and any immediately visible shares:

nmap -p 445 --script "smb-enum-*" <DC01-IP>

Look for this output in the results - it indicates SMB signing is not required, making NTLM relay attacks possible:

| smb2-security-mode:
|   3.1.1:
|_    Message signing enabled but not required
★
CREST CPSA Exam Point: SMB signing disabled or set to "not required" is a critical finding. It means any captured NetNTLMv2 hash can be relayed rather than cracked - bypassing password complexity entirely. Always check this before deciding between relay and capture attacks.
2

Null Session Enumeration with enum4linux-ng

enum4linux-ng

enum4linux-ng is the modern replacement for enum4linux. Run a full null session enumeration against the DC. A null session is an unauthenticated SMB connection - historically common, often still present in Windows Server environments with legacy configuration.

# Full null session enumeration
enum4linux-ng -A <DC01-IP>

The -A flag runs all checks. Key sections to note in the output:

# Domain information - confirms syntex.local
[+] Domain: SYNTEX
[+] Domain SID: S-1-5-21-...

# User enumeration via RID cycling
[+] Users via RPC (null session):
  Administrator (RID 500)
  syntex-admin (RID 1000)
  jsmith (RID 1001)
  svc-backup (RID 1002)

# Share enumeration
[+] Shares via RPC on <DC01-IP>:
  ADMIN$  - Remote Admin
  C$      - Default share
  FINANCE - Syntex Finance Data
  IT-ADMIN - IT Administration
  BACKUP  - Backup Storage
  PUBLIC  - Public Share
  IPC$    - Remote IPC

If null sessions are restricted, try with guest credentials:

enum4linux-ng -A -u "" -p "" <DC01-IP>
⚠
Note: Null session enumeration is noisy. On a real engagement, this will generate Windows Event IDs 4624 (anonymous logon) and 4634 (logoff). On the Syntex DC, Defender and the local firewall are disabled, so you will not be blocked - but record your findings as evidence anyway.
3

Share Enumeration and Access Testing

smbclient

List all available shares with smbclient using a null session:

smbclient -L //<DC01-IP> -N

Now test access to each non-default share. The FINANCE and BACKUP shares are of particular interest:

# Test FINANCE share (null session)
smbclient //<DC01-IP>/FINANCE -N

# Test BACKUP share
smbclient //<DC01-IP>/BACKUP -N

# Test PUBLIC share - likely readable by all
smbclient //<DC01-IP>/PUBLIC -N

Once connected to a share, list and retrieve files:

# Inside smbclient interactive prompt
smb: \> ls
smb: \> get credentials.txt
smb: \> get backup_config.txt
smb: \> exit

The BACKUP share contains a credential file. Download it and examine the contents:

# View the retrieved file
cat credentials.txt

[Backup Service]
Username: svc-backup
Password: Password1
Target: \\SYNTEX-DC01\BACKUP
Created: 2023-10-01 by IT Admin
★
CREST CPSA Exam Point: Credentials stored in SMB shares are a HIGH finding in any assessment report. Document: share name, file name, credential found, and the level of access it grants. svc-backup with Password1 is your first valid domain credential - it unlocks authenticated enumeration in subsequent labs.
4

Authenticated SMB Enumeration

smbmap + CrackMapExec

Now use the svc-backup credential to perform authenticated enumeration with smbmap. This reveals share permissions you cannot see anonymously:

# smbmap with valid credentials - shows READ/WRITE access per share
smbmap -H <DC01-IP> -u svc-backup -p Password1 -d syntex.local

[+] IP: <DC01-IP>:445  Name: SYNTEX-DC01
  Disk        Permissions   Comment
  ----        -----------   -------
  ADMIN$      NO ACCESS     Remote Admin
  C$          NO ACCESS     Default share
  FINANCE     READ ONLY     Syntex Finance Data
  IT-ADMIN    READ ONLY     IT Administration
  BACKUP      READ, WRITE   Backup Storage
  PUBLIC      READ, WRITE   Public Share

Use CrackMapExec to validate the credential and enumerate users and groups quickly:

# Verify credential is valid - look for [+] symbol
crackmapexec smb <DC01-IP> -u svc-backup -p Password1

# Enumerate domain users
crackmapexec smb <DC01-IP> -u svc-backup -p Password1 --users

# Enumerate domain groups
crackmapexec smb <DC01-IP> -u svc-backup -p Password1 --groups

# Check shares with authenticated session
crackmapexec smb <DC01-IP> -u svc-backup -p Password1 --shares
ℹ
SMBv1 Check: The Syntex DC has SMBv1 enabled. Verify this with: nmap -p 445 --script smb-protocols <DC01-IP>. SMBv1 is a HIGH severity finding - it is deprecated, unsupported, and was the transport used by EternalBlue/WannaCry. Include it in the report even if no exploit is attempted.

Knowledge Check

Q1. You run an Nmap scan and see: "Message signing enabled but not required". What attack does this directly enable?

A. Kerberoasting
B. NTLM relay attack
C. Pass-the-Hash
D. AS-REP Roasting

Q2. enum4linux-ng returns a list of domain users via RID cycling without providing any credentials. What SMB misconfiguration does this confirm?

Null sessions are enabled. The server accepts unauthenticated SMB connections and allows RPC queries over IPC$ without credentials. This exposes the full user list - which feeds directly into password spraying, Kerberoasting target selection, and social engineering.

Q3. You find svc-backup / Password1 in a file on the BACKUP share. What is the correct severity rating for this finding in a CPSA report?

A. Low - it is only a service account
B. Medium - credentials in shares are expected
C. High - cleartext credentials on an accessible network share
D. Informational - the password is weak anyway

Key Takeaways

  • SMB signing "not required" enables relay attacks - always check before choosing capture vs relay
  • Null sessions expose user lists, groups, shares, and domain info without authentication
  • Credentials stored in SMB shares are a HIGH finding regardless of account type
  • enum4linux-ng and CrackMapExec are the primary tools for SMB enumeration at CPSA level
  • The credential found here (svc-backup / Password1) enables authenticated enumeration in all subsequent labs
