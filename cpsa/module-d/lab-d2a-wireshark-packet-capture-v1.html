Background

Packet capture is a fundamental network assessment technique. The two tools used in practice are Wireshark (GUI, analysis-focused) and tcpdump (CLI, capture-focused). They use compatible file formats - you capture with tcpdump on a remote host and analyse the .pcap in Wireshark locally.

The critical distinction is between capture filters (BPF syntax, applied during recording) and display filters (Wireshark syntax, applied after). Getting this wrong in an exam costs marks.

Wireshark Display Filter Reference

http.request.method == "POST"HTTP POST requests only - look for login credentials

Steps
1
Start Wireshark and capture HTTP traffic

Open Wireshark on your Kali machine. Select the correct network interface (the one connected to the lab network) and start a capture before generating any traffic.

# Start Wireshark from terminal (or use the GUI directly)
wireshark &

# In Wireshark:
# 1. Select your network interface (usually eth0 or ens33)
# 2. Click the blue shark fin to start capturing
# 3. Apply a capture filter if you want to limit what is recorded:
#    Type in the capture filter box: tcp port 80
ⓘ
If Wireshark shows no interfaces, run it with sudo wireshark or add your user to the wireshark group: sudo usermod -aG wireshark $USER
2
Generate an HTTP login to SYNTEX-LNX01

With Wireshark capturing, trigger a login to the HTTP web application on SYNTEX-LNX01. The login credentials will travel in cleartext inside the POST request body.

# Option A - use a browser
# Navigate to http://<TARGET-IP>/login and submit a login form

# Option B - use curl to send a POST request directly
curl -s -X POST http://<TARGET-IP>/login \
  -d "username=admin&password=Password1" \
  -H "Content-Type: application/x-www-form-urlencoded"
⚠
If the web application is not available on port 80, check what HTTP services are running first: nmap -p 80,8080,8443 <TARGET-IP>
3
Apply display filters to isolate the credentials

Stop the capture. The packet list will contain hundreds of packets. Use display filters to find the login request.

# In the Wireshark display filter bar, type:

# Show only HTTP POST requests
http.request.method == "POST"

# Show all HTTP traffic to/from the target
http and ip.addr == <TARGET-IP>
✓
You should see a single POST packet. Look at the HTML Form URL Encoded section in the packet details pane. The username and password are visible in cleartext.
4
Follow TCP Stream to reconstruct the session

Follow TCP Stream rebuilds the entire HTTP conversation - request and response - in a readable format. Right-click the POST packet and select Follow > TCP Stream.

# In Wireshark GUI:
# Right-click the POST packet
# Follow > TCP Stream
# A new window shows the full request and response in both directions
# Red = client sent, Blue = server sent
What to Look For

The TCP stream will show the full POST body including username and password in cleartext. If the server returns a redirect (HTTP 302) to a dashboard, the login was successful - note this for the report as confirmed credential capture from network traffic.

5
Capture FTP credentials using tcpdump

Now capture traffic on the command line using tcpdump. FTP sends the username and password in plaintext in the control channel before any file transfer begins.

# Start tcpdump, capture only FTP control traffic (port 21), write to file
sudo tcpdump -i eth0 tcp port 21 -w ftp-capture.pcap

# In a second terminal, connect to FTP on SYNTEX-WIN01
ftp <WIN01-IP>
# When prompted:
# Username: jsmith
# Password: Password1

# Press Ctrl+C in the first terminal to stop tcpdump

# Read the pcap with tcpdump to see credentials
tcpdump -r ftp-capture.pcap -A | grep -i "user\|pass"
Expected Output

tcpdump output will include USER jsmith and PASS Password1 in plaintext - these are the FTP control channel commands sent before any file transfer.

6
Analyse the pcap with Statistics > Protocol Hierarchy

Open the ftp-capture.pcap in Wireshark. Use the Statistics menu to get an overview of what protocols are present - this is the fastest way to assess any unknown pcap file during an assessment.

# Open the pcap in Wireshark
wireshark ftp-capture.pcap &

# In Wireshark menu:
# Statistics > Protocol Hierarchy
# This shows every protocol as a percentage of total traffic
# Instantly reveals if HTTP, FTP, Telnet are present

# Statistics > Conversations
# Shows all communication pairs and byte counts
# Identifies the most active hosts
ⓘ
In an exam scenario you may be given a pcap file and asked to identify credentials or protocols. Start with Statistics > Protocol Hierarchy before anything else - it tells you what you are looking for before you start filtering.
Confirmation Questions
1. What is the difference between a Wireshark capture filter and a display filter?
Show answer

A capture filter is applied during recording and uses BPF syntax (e.g. tcp port 80). It limits what is written to disk - packets that do not match are never saved.

A display filter is applied after capture and uses Wireshark syntax (e.g. http.request.method == "POST"). It only changes what is shown - all captured packets are still in the file.

2. What display filter shows only HTTP POST requests in Wireshark?
Show answer

http.request.method == "POST" - the double equals and quoted string are required. This is Wireshark display filter syntax, not BPF.

3. You have captured a large pcap from a client network and need to quickly understand what protocols are in use. What Wireshark menu option do you use first?
Show answer

Statistics > Protocol Hierarchy. This gives an immediate breakdown of every protocol by percentage of total traffic - it tells you whether cleartext protocols (HTTP, FTP, Telnet) are present before you start drilling into individual packets.

4. You have captured FTP traffic but Wireshark is not installed on the remote machine where you ran tcpdump. How do you analyse the capture?
Show answer

Transfer the .pcap file from the remote machine to your local Kali machine using scp, then open it in Wireshark locally: scp user@<remote-ip>:~/capture.pcap .

Alternatively, read it from the command line: tcpdump -r capture.pcap -A or filter with: tcpdump -r capture.pcap -A | grep -i "user\|pass"

5. What does the Follow TCP Stream feature do, and when would you use it during an assessment?
Show answer

Follow TCP Stream reconstructs the full application-layer conversation between two hosts for a given TCP connection. It displays the data in both directions - client to server and server to client - in a readable format.

Use it when you spot a cleartext protocol packet (HTTP, FTP, Telnet) and want to read the full session including credentials, commands, and responses, without reading individual packets.
