Background

SNMP (Simple Network Management Protocol) runs on UDP port 161. Versions 1 and 2c transmit the community string in cleartext - it acts as a password. The default community strings are public (read-only) and private (read-write). If either is present on a live device, an attacker can dump the entire device configuration: routing tables, interfaces, running processes, ARP cache, and user accounts. On Cisco and other network devices, SNMP v2c with the private community string may also allow writing to the device MIB.

Steps
1
Discover SNMP with nmap

Use nmap with a UDP scan and the SNMP NSE script to confirm the service is running and identify what community strings are accepted.

# UDP SNMP discovery with script
nmap -sU -p 161 --script snmp-info <TARGET-IP>

# If --script snmp-info returns nothing, try the broader snmp category:
nmap -sU -p 161 --script snmp* <TARGET-IP>
⚠
UDP scans are slow. nmap will report the port as open|filtered if there is no ICMP unreachable response. That is normal - wait for the script output to confirm a valid response.
Expected Result

nmap should return 161/udp open snmp and the script output will include system information: hostname, OS, uptime, and contact details if configured.

2
Walk the full MIB tree

snmpwalk traverses the entire Management Information Base (MIB) and dumps all values the community string can read. This is the equivalent of a full config dump on a network device.

# Walk the entire MIB tree with community string 'public'
snmpwalk -v2c -c public <TARGET-IP>

# Walk just the system subtree (faster for initial triage)
snmpwalk -v2c -c public <TARGET-IP> 1.3.6.1.2.1.1

# Walk the interface table
snmpwalk -v2c -c public <TARGET-IP> 1.3.6.1.2.1.2.2
ⓘ
A full walk produces a lot of output. Pipe it to less or redirect to a file: snmpwalk -v2c -c public <TARGET-IP> > snmp-dump.txt
Key OID Areas to Note

1.3.6.1.2.1.1 - System info (hostname, description, uptime)
1.3.6.1.2.1.2 - Network interfaces
1.3.6.1.2.1.4.20 - IP address table
1.3.6.1.2.1.25.4.2 - Running processes

3
Get specific OID values

snmpget retrieves a single OID value. Use this when you know exactly what you want - faster and quieter than a full walk.

# Get the system hostname (sysName OID)
snmpget -v2c -c public <TARGET-IP> 1.3.6.1.2.1.1.5.0

# Get the system description (OS, kernel version)
snmpget -v2c -c public <TARGET-IP> 1.3.6.1.2.1.1.1.0

# Get system uptime
snmpget -v2c -c public <TARGET-IP> 1.3.6.1.2.1.1.3.0
What to Record

Note the hostname returned by 1.3.6.1.2.1.1.5.0 - this confirms you are talking to SYNTEX-LNX01. The system description OID will return the Linux kernel version and distribution.

4
Brute force community strings

onesixtyone is built specifically for SNMP community string brute forcing. It is fast because it sends multiple UDP packets without waiting for responses.

# Use the built-in SNMP wordlist
onesixtyone -c /usr/share/wordlists/snmp.txt <TARGET-IP>

# If the wordlist location differs on your system:
locate snmp.txt

# You can also create a minimal wordlist manually:
echo -e "public\nprivate\ncommunity\nnetwork\nmanager\nadmin" > snmp-words.txt
onesixtyone -c snmp-words.txt <TARGET-IP>
⚠
Assessment note: Aggressive UDP brute forcing can cause instability on production network devices. On a real engagement, agree SNMP testing scope with the client before running onesixtyone at full speed.
Expected Result

onesixtyone will print the IP and community string for each successful response: <TARGET-IP> [public] Linux SYNTEX-LNX01 ...

5
Enumerate running processes

The HOST-RESOURCES-MIB contains running process information. On a network device this would reveal management software versions. On a Linux server it reveals what services are active - useful for further attack planning.

# Enumerate running processes via SNMP
snmpwalk -v2c -c public <TARGET-IP> 1.3.6.1.2.1.25.4.2

# Filter for process names only (column 2 of the hrSWRunTable)
snmpwalk -v2c -c public <TARGET-IP> 1.3.6.1.2.1.25.4.2.1.2
Why This Matters

Process enumeration via SNMP reveals services running on the target - web servers, databases, monitoring agents - without needing to touch any application port directly. This information goes directly into the assessment report as an unauthenticated information disclosure finding.

Confirmation Questions
1. What community string did onesixtyone confirm on SYNTEX-LNX01?
Show answer

public - the default read-only community string. This is a HIGH severity finding - the device is using the out-of-the-box default, meaning any attacker with network access can dump its configuration without any credentials.

2. What OID do you query to retrieve the system hostname?
Show answer

1.3.6.1.2.1.1.5.0 - this is the sysName OID in the system MIB subtree. The trailing .0 is required for scalar objects.

3. You discover a read-write community string (private) is also active. What additional risk does this introduce beyond information disclosure?
Show answer

A read-write community string allows an attacker to write values to the MIB. On a network device this could mean modifying routing tables, disabling interfaces, or changing the device configuration. In extreme cases (Cisco IOS), it can be used to overwrite the running config or firmware. This escalates the finding from HIGH to CRITICAL.

4. Which SNMP version should be recommended as a remediation, and why?
Show answer

SNMPv3 - it introduces authentication (MD5 or SHA) and encryption (DES or AES). SNMPv1 and v2c transmit community strings in cleartext over UDP, making them trivially interceptable with Wireshark or tcpdump on the same network segment. If SNMPv3 cannot be deployed, SNMP should be disabled entirely and replaced with a management protocol that supports authentication.
