Banner Grabbing and Service Identification

Extract service banners from open ports using multiple techniques. Identify software versions, OS clues, and configuration details exposed in banners. Understand what banner information an attacker can use and what it means for the organisation.

🔌 Target Connectivity Check

Enter your target IP(s) and click Check to verify the VMs are reachable before you start.

Scenario

You have a list of open ports on both Syntex Solutions targets. Service banners - the text a service presents when you first connect - are a goldmine of intelligence. Software versions link directly to CVEs. Configuration details reveal deployment decisions. In some cases, developers leave credentials in banners. Your job is to systematically grab and analyse every banner available.

Learning Objectives
  • Grab banners from SSH, FTP, HTTP, and SMB services using multiple tools
  • Identify software versions and link them to known vulnerabilities
  • Extract intelligence from HTTP headers and HTML source comments
  • Understand which banner suppression techniques defenders use and how to work around them

Part 1 - Manual Banner Grabbing with Netcat
1
SSH Banner

SSH presents a banner immediately on connection before any authentication is attempted. This banner contains the SSH protocol version and the server software version.

# Grab the SSH banner with netcat
nc -nv <LNX01-IP> 22

# You will see something like:
SSH-2.0-OpenSSH_8.2p1 Ubuntu-4ubuntu0.9

# Press Ctrl+C to disconnect
ℹ
Reading the SSH banner: SSH-2.0 is the protocol version. OpenSSH_8.2p1 is the software and version. Ubuntu-4ubuntu0.9 is the OS package suffix - this tells you the distribution (Ubuntu) and patch level. Cross-reference the version against CVE databases.
SSH banner from SYNTEX-LNX01
2
FTP Banner

FTP servers typically present a banner on connection that includes the server software and sometimes the hostname.

# Grab FTP banner with netcat
nc -nv <LNX01-IP> 21

# Expected banner format:
220 Syntex Solutions FTP Server - Authorised Users Only

# Type QUIT to disconnect cleanly
QUIT

Part 2 - HTTP Header Analysis
3
HTTP Response Headers from SYNTEX-DC01

HTTP response headers expose the web server software and version. The Server header is the most valuable for fingerprinting IIS installations.

# Grab HTTP headers only (HEAD request)
curl -I http://<DC01-IP>/

# Verbose output showing full request and response
curl -v http://<DC01-IP>/ 2>&1 | head -40

Look for these headers in the response:

HeaderWhat It Reveals
Server:Web server software and version (e.g. Microsoft-IIS/10.0)
X-Powered-By:Backend technology (e.g. ASP.NET)
X-AspNet-Version:.NET framework version
Set-Cookie:Session technology, sometimes framework hints
Date:Server time zone - useful for timing attacks
HTTP headers from SYNTEX-DC01
4
HTML Source Analysis - Finding Comments

Developers sometimes leave sensitive information in HTML comments. These are invisible to normal browsers but trivially accessible to an attacker. Always view source on any web page you find.

# Download and view the page source
curl http://<DC01-IP>/

# Grep specifically for HTML comments
curl http://<DC01-IP>/ | grep -i "<!--"

# Also check for common sensitive paths
curl http://<DC01-IP>/robots.txt
curl http://<DC01-IP>/web.config 2>/dev/null
★
CREST Exam Point: If you find credentials or internal information in HTML comments, this is a High severity finding. Document exactly: the URL, the comment text verbatim, what information it reveals, and the risk. "Developer comments expose credentials and internal infrastructure details" is a real finding category in CREST reports.
HTML comments found in the Syntex intranet page
5
WhatWeb for Automated Banner Analysis

WhatWeb automates the process of identifying web technologies from headers, cookies, and page content.

# Standard WhatWeb scan
whatweb http://<DC01-IP>/

# Verbose output
whatweb -v http://<DC01-IP>/

# Aggressive mode (more requests)
whatweb -a 3 http://<DC01-IP>/

Part 3 - nmap Banner Scripts
6
Automated Banner Grabbing with nmap

nmap's banner script automates banner grabbing across multiple ports in a single scan.

# Banner grab all open ports on LNX01
sudo nmap --script banner -p 21,22,139,445,2049 <LNX01-IP>

# Version detection also pulls banners
sudo nmap -sV --version-intensity 9 -p 21,22 <LNX01-IP>
