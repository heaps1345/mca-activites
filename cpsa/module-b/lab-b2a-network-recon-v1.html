Passive Network Recon

Passive recon means gathering information without sending probes to targets. You are using data already present on your machine or generated by normal network traffic. This lab covers ARP cache inspection, local host file mapping, and capturing live traffic with Wireshark to observe protocols in action.

▶ Pre-Lab Checklist

Complete Lab B1-A before this one. You need your IP address, gateway, and subnet from that lab.

  • Lab B1-A completed - you know your IP, gateway, and subnet
  • Kali terminal is open
  • Wireshark is installed (check: which wireshark)
Objectives
  • Read the ARP cache to identify other hosts on the local network without scanning
  • Understand what Layer 2 information is available passively
  • Read local host file mappings
  • Capture live traffic with Wireshark and identify ICMP packet types
  • Connect B2 theory - switches, routers, ARP - to what you can observe from a Kali shell
Background - Why Passive Recon First
⚠
Active scanning generates log entries. Every nmap scan you run is potentially recorded by IDS/IPS, firewall logs, and endpoint detection. Passive recon - reading data that is already there - generates no traffic and leaves no trace. On a real engagement, you exhaust passive sources before you touch active tools.

The ARP cache is a free host list. Your machine has been talking to other devices on the network already - via DHCP, DNS, default gateway traffic. All of those conversations left ARP entries mapping IP addresses to MAC addresses. Reading that cache costs you nothing.

Part 1 - ARP Cache Inspection
1
Read the ARP cache

ARP (Address Resolution Protocol) maps IP addresses to MAC addresses at Layer 2. Your machine maintains a cache of recent ARP entries - every host it has communicated with recently.

# Show the ARP cache
arp -n

# Alternative using ip (modern equivalent)
ip neigh

The -n flag on arp means "numeric - don't try to resolve IPs to hostnames." This keeps output clean and fast.

The ip neigh output shows each entry's state: REACHABLE means the entry was confirmed recently, STALE means it has not been verified recently but may still be valid.

Record ARP entries found
ℹ
MAC address OUI: The first three bytes of a MAC address (e.g. 00:50:56) identify the manufacturer. VMware, VirtualBox, and Hyper-V all have known prefixes - which tells you the host is a VM. This is useful recon on a real engagement.
2
Generate new ARP entries by pinging

Ping a host on your subnet. Before it can send the ICMP packet, your machine must resolve the target's MAC address via ARP. After the ping completes, a new ARP entry will appear in your cache.

# Ping another host on your subnet (ask your instructor for a target IP)
ping -c 2 <TARGET_IP>

# Now check the ARP cache again
arp -n
Did a new ARP entry appear?
Part 2 - Local Host Mappings
3
Read the hosts file

Before DNS, your machine checks /etc/hosts for static name-to-IP mappings. On a lab environment this may contain pre-configured target hostnames. On a real engagement, finding the hosts file on a compromised machine can reveal internal hostnames that do not appear in external DNS.

cat /etc/hosts
What entries are in your hosts file?
✓
Attackers modify /etc/hosts to redirect traffic during man-in-the-middle attacks. If you are doing a post-compromise review, checking for unexpected entries here is a standard step.
Part 3 - Wireshark - Observe ICMP in the Wild
ℹ
This part bridges B1 theory to live traffic. You will capture a ping and see the ICMP Type 8 (Echo Request) and Type 0 (Echo Reply) packets in real time. Wireshark is the industry standard for packet analysis and appears in CREST exam scenarios.
4
Start a Wireshark capture

Launch Wireshark. You can use the GUI or start it from the terminal. Select your active network interface (the one with your IP address - eth0, ens33, etc.).

# Launch Wireshark GUI
wireshark &

# Or capture from command line and open in Wireshark after
tcpdump -i eth0 -w /tmp/capture.pcap -c 20

In the Wireshark GUI, double-click your interface to start capturing. Apply the display filter icmp in the filter bar at the top to show only ICMP traffic.

⚠
If Wireshark says "permission denied" on the interface, run it as root: sudo wireshark &
5
Generate ICMP traffic and observe it

With Wireshark capturing, open a second terminal and ping your gateway. Watch the packets appear in real time.

# In a second terminal - replace with your gateway IP
ping -c 4 <YOUR_GATEWAY_IP>

In Wireshark you should see alternating request/reply pairs. Click on one to expand it in the lower panes and find the ICMP type field.

From the Wireshark capture
🎯
CREST Exam Link: The exam may show a Wireshark screenshot or packet hex dump and ask you to identify the protocol, type, and direction. ICMP Type 8 = request (outbound). ICMP Type 0 = reply (inbound). Know them without thinking.
6
Observe a DNS query in Wireshark

Change the Wireshark display filter to dns. Then run a DNS lookup from your terminal.

# In a second terminal
dig google.com

You should see a DNS query (port 53, UDP) leave your machine and a response come back. Click the query packet and expand it - you will see the question section (what was asked) and the answer section (what was returned).

From the DNS capture

Exam-Style Questions
Q1

What protocol does a host use to discover the MAC address of another host on the same subnet before it can send IP traffic to it?

Q2

A host responds to ICMP Echo Requests but its ARP entry shows a MAC address beginning with 00:0C:29. What does this tell you about the host?

00:0C:29 is a VMware OUI (Organizationally Unique Identifier). This indicates the host is a VMware virtual machine. This is useful recon - virtual machines often have known default configurations, shared clipboard enabled, or other VM-specific attack surfaces.
Q3

You are on a network and your ARP cache shows three entries besides your gateway. Without running nmap, what is the minimum number of live hosts you know exist on the subnet?

At least four - the three in the ARP cache plus your gateway. The ARP cache only shows hosts your machine has communicated with. There may be many more hosts on the subnet that have not communicated with you. The ARP cache is a minimum bound, not a complete picture.
Q4

What layer of the TCP/IP model does ARP operate at, and what two things does it map together?

ARP operates at Layer 2 (Network Access / Data Link). It maps IP addresses (Layer 2 / Internet layer) to MAC addresses (Layer 1 / Network Access layer). ARP is what allows IP networking to work over Ethernet - without it, your machine would not know which Ethernet frame to send an IP packet in.
Q5

Why might a DNS server and a domain controller share the same IP address on a Windows network?

Active Directory uses DNS to locate services - domain controllers register SRV records that clients use to find the DC, Kerberos, LDAP and other AD services. Microsoft recommends running DNS on the domain controller itself for this reason. Finding that the DNS server also responds on port 88 (Kerberos) or 389 (LDAP) is a strong indicator that it is the domain controller.
✓ Lab Complete - Key Takeaways
Passive recon costs you nothing and leaves no trace. Before you run a single nmap scan, you already know your position on the network, your gateway, your DNS server, and every host that has communicated with your machine since boot. In Wireshark, you can confirm ICMP Type 8 and 0 by eye - which links directly to the CREST exam theory. Next lab covers service enumeration: now you will start sending probes to targets.
