Interpreting and Documenting Tool Output

Run live enumeration tools, extract meaningful intelligence from their output, and translate raw results into professional findings. This lab tests whether you understand what the tools are telling you - not just how to run them.

Scenario

Your port scan of the Syntex Solutions environment is complete. You now have two targets with multiple open services. The next phase is enumeration: using specialised tools to interrogate each service and pull out intelligence. The challenge in the CREST exam is not running the tools - it is proving you understand what the output means and can extract findings from it.

Learning Objectives
  • Run service enumeration tools and interpret their output correctly
  • Extract specific intelligence from SMB, FTP, NFS, and LDAP enumeration
  • Distinguish between a finding and background noise in tool output
  • Produce structured notes from raw tool output
  • Understand what each piece of output means for a penetration tester

Part 1 - SMB Enumeration
1
enum4linux Against SYNTEX-LNX01

enum4linux is a wrapper around Samba tools that automates SMB enumeration. It attempts to pull users, groups, shares, password policy, and OS information from a target.

# Full enum4linux scan
enum4linux -a <LNX01-IP>

# Save output
enum4linux -a <LNX01-IP> | tee enum4linux-lnx01.txt

The output is verbose. Focus on these sections:

Section Header in OutputWhat to Extract
Enumerating Workgroup/DomainDomain/workgroup name
Session Check onNull session allowed? Yes/No
Getting domain SIDSID string if returned
Share EnumerationShare names and access level
Password Policy InformationMin length, complexity, lockout
Users onUsername list
Key findings from enum4linux on SYNTEX-LNX01
2
Accessing the SMB Share

If enum4linux found accessible shares, use smbclient to browse them. The goal is to identify any sensitive files left accessible.

# List shares with null session (no credentials)
smbclient -L //<LNX01-IP> -N

# Connect to the data share
smbclient //<LNX01-IP>/data -N

# Inside smbclient - list files
smb: \> ls
smb: \> get budget_draft.txt
smb: \> get staff.txt
smb: \> exit
★
CREST Exam Point: Finding and accessing a share with sensitive data is a finding. Document: share name, authentication required (none in this case), files accessible, sensitivity of those files. A null session share with staff data is a medium or high finding depending on data sensitivity.
Files retrieved from the SMB share - summarise their contents
3
enum4linux Against SYNTEX-DC01

A domain controller will return significantly more data than a standalone Linux host. Pay close attention to the password policy and any share names that suggest sensitive content.

# Full enum4linux against the Windows DC
enum4linux -a <DC01-IP> | tee enum4linux-dc01.txt

# Also try enum4linux-ng (newer version, better against modern Windows)
enum4linux-ng <DC01-IP> -A | tee enum4linux-ng-dc01.txt
ℹ
What to look for on a DC: Domain name, domain SID, list of domain users, password policy (minimum length, complexity, lockout threshold), share names including SYSVOL and NETLOGON, and whether anonymous sessions are permitted.

Part 2 - FTP Enumeration
4
Anonymous FTP Login

Anonymous FTP login is a classic misconfiguration. If the server accepts the anonymous username, any unauthenticated user can browse and download files.

# Connect to FTP and try anonymous login
ftp <LNX01-IP>

# At the login prompt:
Name: anonymous
Password: (press enter or enter any email)

# If logged in - list files
ftp> ls
ftp> ls -la
ftp> get welcome.txt
ftp> quit
# Alternative: use curl to browse FTP anonymously
curl ftp://<LNX01-IP>/ --user anonymous:
curl ftp://<LNX01-IP>/welcome.txt --user anonymous:
★
CREST Exam Point: Anonymous FTP is always a finding. Even if the only file is a welcome message, the misconfiguration must be reported. Record: service version from the banner, anonymous login permitted (Y/N), files accessible, and whether write access is enabled (higher severity).

Part 3 - NFS Enumeration
5
Enumerating and Mounting NFS Exports

NFS (Network File System) allows remote directories to be mounted over the network. Misconfigured exports can expose sensitive files to anyone on the network.

# Show available NFS exports
showmount -e <LNX01-IP>

# Mount the export
mkdir /tmp/nfs-mount
sudo mount -t nfs <LNX01-IP>:/exports/data /tmp/nfs-mount

# Browse the mounted share
ls -la /tmp/nfs-mount/
cat /tmp/nfs-mount/db.conf
cat /tmp/nfs-mount/passwd.bak

# Unmount when done
sudo umount /tmp/nfs-mount
⚠
no_root_squash: Check the export options from showmount. If you see no_root_squash, root on your Kali machine has full root access to the NFS export. This means you can write files as root, including SUID binaries or SSH keys. This is a critical finding in a real engagement.

Annotate the enum4linux Output

Analysis Q1

The output shows "Server DC01 allows sessions using username '', password ''". What is the security implication of this?

Analysis Q2

The minimum password length is 4 and complexity flags are 000000. What does this mean in practice and what attack does it enable?

Analysis Q3

You can see shares named FINANCE, IT-ADMIN, BACKUP and HR. What is your next step and what would you be looking for?

Knowledge Check
Q1

enum4linux returns a large amount of output. What are the three most valuable sections to focus on for a penetration test and why?

Q2

You find an NFS export with the option no_root_squash. Explain what this means and describe one concrete attack this enables.

Q3

FTP returns a 230 response code after you enter the username "anonymous". What does 230 mean and what should you do next?

Q4

You are enumerating a domain controller. enum4linux shows a minimum password length of 1. Why is this particularly significant in the context of an Active Directory environment?

★
Lab Complete - Key Takeaways: Tool output is only useful if you can read it. CREST examiners test whether you can identify findings within output, explain their significance, and link them to real attack techniques. A candidate who can run enum4linux and say "null session enabled means I can enumerate users without credentials, enabling a password spray attack" will always score higher than one who just pastes the output.
