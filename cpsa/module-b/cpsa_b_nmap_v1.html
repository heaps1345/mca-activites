01 - Port States

Nmap reports six possible port states. CREST candidates must be able to explain each one precisely - especially the difference between closed and filtered, and why open|filtered is unreliable.

open
An application is actively listening. For TCP: a SYN-ACK was received in response to a SYN probe. This is what you are looking for.
closed
The port is accessible but nothing is listening. For TCP: an RST was received. The host is reachable, the port just has no service bound to it.
filtered
Nmap cannot determine if the port is open or closed. No response arrived, or an ICMP unreachable was returned. A firewall is likely dropping or rejecting packets.
unfiltered
The port is reachable but nmap cannot determine open or closed. Only appears in ACK scan results - it means the packet got through, not that a service is running.
open|filtered
Nmap cannot tell whether the port is open or filtered. UDP and stealthy scan types (FIN, Null, Xmas) produce this when no response arrives - both states produce silence.
closed|filtered
Only seen in IP ID idle scans. Nmap cannot determine whether the port is closed or filtered.
Exam trap: Filtered and closed are completely different. Closed means the host responded with RST - you can reach it, nothing is running. Filtered means you got no response or an ICMP unreachable - a device is blocking the probe. Many candidates mix these up under time pressure.

02 - Scan Types

Each scan type sends different packets and interprets the response differently. You need to know which flag is set, what privilege level is required, and when to use each one.

Flag Scan Type Packets Sent Open Response Closed Response Root? Notes
-sS SYN / Half-open SYN SYN-ACK RST Yes Default when root. Fast, low noise, does not complete handshake
-sT TCP Connect Full handshake Connection established RST or refused No Default without root. Uses OS connect(). Fully logged at application level
-sU UDP UDP packet Varies or none ICMP port unreachable Yes Slow and unreliable. No response = open|filtered. Use --top-ports 20 in exams
-sA ACK ACK RST (unfiltered) RST (unfiltered) Yes Does NOT detect open ports. Used to map firewall rules - RST means unfiltered
-sF FIN FIN No response RST Yes Bypasses some stateless firewalls. Unreliable on Windows targets
-sN Null No flags set No response RST Yes Same RFC 793 trick as FIN. Unreliable on Windows
-sX Xmas FIN+PSH+URG No response RST Yes All three flags lit. Same logic as Null and FIN. Unreliable on Windows
-sW Window ACK RST with positive window RST with zero window Yes Exploits TCP window field quirks on some OS stacks
-sM Maimon FIN+ACK No response RST Yes Named after researcher Uriel Maimon. Works on some BSD-derived stacks
-sI Idle / Zombie SYN via zombie IP ID increment IP ID unchanged Yes True blind scan - source IP is a third party "zombie" host
Key distinction: -sA is not a port-finding scan. It tells you whether a port is filtered or unfiltered by the firewall - both open and closed ports return RST (unfiltered) if packets get through. Use it after -sS to understand firewall behaviour, not to find services.

03 - Timing Templates

Nmap has six timing templates controlled with -T0 through -T5. They affect probe timing, parallelism, and timeout thresholds. Slower templates are harder for IDS to detect but take far longer to complete.

-T0
Paranoid
One probe every 5 minutes. IDS evasion. Used when you must not be detected and have days to spare.
-T1
Sneaky
One probe every 15 seconds. Still very slow. For stealthy engagements with more time.
-T2
Polite
0.4 second delay between probes. Reduces bandwidth and target load. Avoids overloading fragile systems.
-T3
Normal
Default. Nmap's own adaptive timing. Balances speed and accuracy with no manual adjustment.
-T4
Aggressive
Assumes a fast, reliable network. Good for lab environments and CTFs. Can cause missed ports on slow or congested networks.
-T5
Insane
Sacrifices accuracy for maximum speed. Will miss ports on anything other than a local LAN. Rarely used professionally.
Lab vs real world: -T4 is fine for the CPSA lab environment. In a real engagement, -T3 is the safer default - T4 will generate enough noise to trigger most modern IDS. Never use -T5 against production targets.

04 - OS Detection

Nmap's OS detection (-O) sends a series of TCP, UDP and ICMP probes and compares the responses against a database of over 2,600 known OS fingerprints. It analyses multiple fields to make a determination.

Probe / Field What Nmap Analyses
TCP ISN Randomness pattern of Initial Sequence Numbers - different OS classes have different generation algorithms
TCP Options Which options are present, their order, and values (MSS, window scaling, timestamps, SACK)
IP TTL Starting TTL values - Linux typically starts at 64, Windows at 128, Cisco IOS at 255
Window Size Default TCP window sizes vary by OS and version
DF Bit Whether the Don't Fragment bit is set in IP headers
ICMP Responses How the target responds to malformed ICMP packets - many OS stacks handle these differently
TCP Closed Port Response RST packet contents and flags differ between OS implementations
# Basic OS detection - requires root, needs at least one open and one closed port sudo nmap -O <target> # Aggressive OS detection - tries harder, more probes sudo nmap -O --osscan-guess <target> # Combined: OS detection + version + scripts + traceroute sudo nmap -A <target>
CREST exam angle: You will be asked about TTL-based OS fingerprinting. Know the defaults: Linux/Unix = 64, Windows = 128, Cisco IOS = 255. Nmap's -O does far more than just TTL analysis but TTL is the quick manual indicator when you are reading a packet capture.
-O requires: Root privileges, and nmap needs at least one open and one closed port to make a determination. If all ports are filtered, OS detection will fail or return no match.

05 - Version Detection

Version detection (-sV) sends additional probes to open ports and attempts to identify the service, protocol, application name and version number. This is what tells you "OpenSSH 8.2p1" rather than just "port 22 open".

# Standard version detection sudo nmap -sV <target> # Maximum intensity - sends more probes, slower but more thorough sudo nmap -sV --version-intensity 9 <target> # Intensity scale: 0 (fastest, only most likely probes) to 9 (all probes) # Default intensity is 7 # Combined with SYN scan (most common real-world command) sudo nmap -sS -sV -p- <target>

Version detection works by sending protocol-specific probes and matching the responses against the nmap-service-probes database. It can also trigger NSE scripts that run against detected services automatically when combined with -sC.

06 - NSE Scripts

The Nmap Scripting Engine (NSE) allows nmap to run Lua scripts against targets. Scripts are categorised by function. Understanding the categories is an exam requirement - you need to explain what each one does and when you would use it.

Category What It Does Example Scripts
auth Tests authentication credentials and bypass techniques against services ftp-anon, ssh-auth-methods, http-auth
broadcast Discovers hosts and services on the local network via broadcast packets - does not need a target IP broadcast-dhcp-discover, broadcast-dns-service-discovery
brute Performs brute-force password attacks against services ftp-brute, ssh-brute, http-brute, smb-brute
default Scripts that run with -sC or -A. Safe, fast, commonly useful ssh-hostkey, http-title, smb2-security-mode
discovery Retrieves information about target - usernames, shares, DNS records smb-enum-shares, dns-zone-transfer, snmp-info
dos Tests for denial-of-service vulnerabilities. Use with explicit permission only http-slowloris, smb-flood
exploit Attempts to exploit vulnerabilities - goes beyond detection ms17-010 (EternalBlue)
external Sends data to third-party databases (Whois, GeoIP). Leaks target info externally whois-ip, ip-geolocation-maxmind
fuzzer Sends unexpected or random data to find crashes and unexpected behaviour dns-fuzz
intrusive Likely to crash services or cause denial of service. Never run without authorisation http-shellshock, ftp-vsftpd-backdoor
malware Checks for signs of compromise - backdoors, rootkits, C2 connections smtp-strangeport, auth-spoof
safe Scripts unlikely to crash services or use excessive bandwidth ssl-cert, http-headers, banner
version Used internally by -sV. Extends service version detection Various service probes
vuln Checks for specific vulnerabilities - reports whether a target appears vulnerable smb-vuln-ms17-010, ssl-heartbleed, http-shellshock
# Run default scripts (same as -sC) sudo nmap --script default <target> # Run all scripts in a category sudo nmap --script vuln <target> # Run a specific named script sudo nmap --script smb-vuln-ms17-010 <target> # Run multiple specific scripts sudo nmap --script smb2-security-mode,smb-protocols <target> # Run all SMB-related scripts (wildcard) sudo nmap --script "smb-*" <target> # Run scripts with arguments (e.g. pass credentials) sudo nmap --script smb-enum-shares --script-args smbusername=admin,smbpassword=password <target>
CREST exam point: Know the difference between safe, default, intrusive and vuln categories. If asked "what scripts would you run first", the answer is default or safe. Never run brute, dos, exploit or intrusive categories without specific authorisation - these go beyond reconnaissance.

07 - Output Formats

Always save your scan output. CREST examiners want to see that you have documented your findings. Nmap supports five output formats.

Flag Format Extension Use Case
-oN Normal .nmap / .txt Human-readable output. What you see in the terminal. Good for reports.
-oX XML .xml Machine-readable. Importable into Metasploit, Nessus, and other tools.
-oG Grepable .gnmap One host per line. Easy to parse with grep, awk, and cut.
-oS Script kiddie - Leetspeak output. No practical use - never use in a professional context.
-oA All formats .nmap + .xml + .gnmap Saves all three useful formats at once. Best practice on engagements.
# Save all formats - best practice for real engagements sudo nmap -sS -sV -p- -oA scan-results <target> # This creates: scan-results.nmap, scan-results.xml, scan-results.gnmap # Parse grepable output to find open ports quickly grep "Ports:" scan-results.gnmap | grep "open"

08 - Evasion Techniques

Nmap includes several flags that can help bypass firewalls and IDS. These are tested in CPSA and you need to know what each one does - not just the flag name.

Flag Technique What It Does
-f Fragment packets Splits TCP header across multiple IP fragments. Older firewalls and IDS reassemble before inspecting - some do not.
--mtu <size> Custom MTU Sets a specific fragment size (must be a multiple of 8). More control than -f.
-D <decoy1,decoy2,...> Decoy scan Sends spoofed packets from decoy IPs alongside your real probes. The target sees multiple source IPs and cannot determine the real attacker.
-S <IP> Spoof source IP Sends packets with a spoofed source address. You cannot receive responses unless routing supports it - usually used with -e and -Pn.
--source-port <port> Spoof source port Sets the TCP/UDP source port. Some firewalls trust traffic from port 53 or 80 - this exploits that misconfiguration.
--data-length <n> Pad packets Appends random data to packets to change their size. Breaks signatures that match on packet length.
--randomize-hosts Randomise scan order Scans hosts in random order rather than sequentially. Harder for IDS to correlate as a single scan event.
--scan-delay <time> Manual probe delay Sets a fixed delay between probes. Supplements timing templates for fine-grained rate control.
--spoof-mac <vendor> MAC address spoof Spoofs the source MAC address. Only effective on the local segment - does not cross routers.
Authorisation required: Evasion techniques do not make scanning legal - they just make it harder to attribute. Always have written authorisation before using any of these in a real engagement.

09 - Common Command Reference

These are the commands you will use most often in the CPSA lab and exam. Know these by heart.

# Host discovery - ping sweep, no port scan sudo nmap -sn 192.168.1.0/24 # Full TCP SYN scan, all ports, version detection, save all formats sudo nmap -sS -sV -p- -oA results <target> # Combined: OS + version + default scripts + traceroute sudo nmap -A <target> # Full port scan, aggressive timing (lab use) sudo nmap -sS -p- -T4 <target> # UDP scan, top 20 ports only sudo nmap -sU --top-ports 20 <target> # Run default NSE scripts with version detection sudo nmap -sS -sV -sC <target> # Run vuln scripts against specific ports sudo nmap -sV --script vuln -p 445,80,443 <target> # Skip host discovery (treat all hosts as up) - useful when ICMP is blocked sudo nmap -sS -Pn <target> # Scan specific ports only sudo nmap -sS -p 22,80,443,445,3389 <target> # Verbose output - shows results as they come in sudo nmap -sS -v <target> # Fragment packets and use decoys for evasion sudo nmap -sS -f -D RND:5 <target>
