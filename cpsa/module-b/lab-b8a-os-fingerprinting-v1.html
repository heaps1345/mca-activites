OS Fingerprinting and Host Identification

Identify the operating system and host characteristics of live targets using active fingerprinting techniques, service banners, and TTL analysis. Understand what the evidence tells you and how confident you should be in your assessment.

Part 1 - TTL Analysis
1
Reading TTL Values from Ping

Before running nmap, you can make an educated OS guess just from the ping TTL. Different operating systems start with different default TTL values. This takes seconds and requires no special tools.

# Ping both targets and note the TTL value
ping -c 4 <LNX01-IP>
ping -c 4 <DC01-IP>

Look for the TTL= value in the response. Use this reference table:

TTL Value (approx)Likely OSNotes
64Linux / macOSDefault Linux TTL is 64
128WindowsDefault Windows TTL is 128
255Cisco IOS / SolarisNetwork devices often use 255
Values lower than defaultAny of the aboveEach router hop decrements by 1
ℹ
Why TTL decrements: Each router hop reduces the TTL by 1. A response of 63 instead of 64 means one hop between you and the target. A response of 127 means one hop from a Windows machine. Always account for routing when interpreting TTL.

Part 2 - nmap OS Detection
2
Active OS Fingerprinting with nmap -O

nmap's OS detection (-O) sends a series of specially crafted packets and analyses the responses to match TCP/IP stack behaviour against a database of known OS fingerprints. It requires root privileges and at least one open and one closed port.

# OS detection against both targets
sudo nmap -O <LNX01-IP>
sudo nmap -O <DC01-IP>

# Combined OS + version detection (more information)
sudo nmap -O -sV <LNX01-IP>

# Aggressive scan (OS + version + scripts + traceroute)
sudo nmap -A <DC01-IP>
★
CREST Exam Point: nmap shows an OS match with a confidence percentage. "OS details: Windows Server 2016 (98%)" means nmap is 98% confident. Always quote the confidence in your notes. If confidence is below 80%, document that the OS could not be determined with certainty and explain what other evidence you used to reach your assessment.

3
Corroborating with Service Banners

OS detection from packet behaviour can be blocked or fooled. Service banners - the text a service returns when you connect - often confirm the OS directly. Cross-reference these with your nmap -O result.

# SSH banner grab (Linux)
nc -nv <LNX01-IP> 22

# FTP banner grab
nc -nv <LNX01-IP> 21

# HTTP banner grab from IIS (Windows DC)
curl -I http://<DC01-IP>/

# WinRM banner
curl -I http://<DC01-IP>:5985/
ℹ
What to look for in banners: SSH banners often include the OS (e.g. Ubuntu-4ubuntu0.3). FTP banners show server software. HTTP Server headers show IIS version (e.g. Microsoft-IIS/10.0 maps to Windows Server 2016/2019). These are passive and do not require sending crafted packets.

4
Port Profile Analysis

Even without OS detection or banners, a port profile tells a story. Certain combinations of open ports are unique to specific OS roles.

Port ProfileLikely OS / Role
22, 21, 2049, 139, 445Linux server - SSH, FTP, NFS, Samba
53, 88, 135, 389, 445, 464, 636, 3268, 3389Windows Active Directory Domain Controller
80, 443, 8080Web server - platform unclear without banner
3389 onlyWindows desktop / server, no AD role
1433 + 445Windows with SQL Server
5985, 5986Windows with WinRM enabled

5
nmap OS Scripts

nmap NSE scripts can pull additional OS and host information beyond basic fingerprinting.

# SMB OS detection script (Windows)
sudo nmap --script smb-os-discovery <DC01-IP>

# This returns OS version, computer name, domain, and FQDN
# Example output you should see:
Host script results:
| smb-os-discovery:
|   OS: Windows Server 2016 Standard 14393 (Windows Server 2016 Standard 6.3)
|   OS CPE: cpe:/o:microsoft:windows_server_2016
|   Computer name: SYNTEX-DC01
|   NetBIOS computer name: SYNTEX-DC01
|   Domain name: syntex.local
|   Forest name: syntex.local
|   FQDN: SYNTEX-DC01.syntex.local
|_  System time: 2024-01-15T14:23:41+00:00
★
CREST Exam Point: smb-os-discovery gives you the computer name, domain name, and exact OS version in one script. This is extremely valuable - you get the AD domain name (syntex.local), the hostname (SYNTEX-DC01), and confirmation of the OS build number. Always run this against any Windows host with SMB open.

Lab Complete - Key Takeaways: OS fingerprinting is about building confidence through corroboration. TTL gives you a starting point, nmap -O gives you a probability, service banners give you hard evidence, and smb-os-discovery can give you the exact OS version and AD domain. A strong CREST candidate cross-references all available sources and documents both the finding and their confidence level.
