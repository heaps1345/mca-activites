Process and Socket Enumeration

Enumerate running processes, open network sockets, and active connections on both Linux and Windows targets. Understand what each discovered service reveals and how to map process-to-port relationships - a critical skill for both privilege escalation and lateral movement.

Scenario

You have low-privilege access to both Syntex Solutions targets. Before attempting privilege escalation, a thorough tester enumerates all running processes and open network connections. This reveals services that port scans miss (internal-only listeners), processes running as privileged users, and potential attack surface that would otherwise go unnoticed. This lab builds the enumeration skills that feed directly into privilege escalation planning.

Learning Objectives
  • Use ps, top and /proc to enumerate running processes on Linux
  • Use ss and netstat to list open sockets and active connections
  • Identify services listening only on localhost (internal attack surface)
  • Enumerate Windows processes and connections with tasklist and netstat
  • Correlate PIDs to processes and understand what each service means

Full Process Listing

The ps command shows running processes. The flags matter: aux shows all processes for all users with full details.

# All processes, all users, with details
ps aux

# Full command lines - shows script paths and arguments
ps auxww

# Tree view showing parent-child relationships
ps auxf

# Processes running as root (high value targets)
ps aux | grep "^root"
ℹ
What to look for: Processes running as root that have exploitable configurations, database daemons running locally (MySQL, PostgreSQL), web servers running internally, and any custom/non-standard process names that suggest bespoke applications.
Process enumeration - notable findings
3
Read Process Details from /proc

The /proc filesystem exposes detailed information about every running process. Each PID has its own directory with full command line, environment variables, and open file descriptors.

# Get the PID of a process first
ps aux | grep ssh

# Read the full command line of a specific PID
cat /proc/<PID>/cmdline | tr '\0' ' '

# Read environment variables for the process
# (this may contain credentials if devs are lazy)
cat /proc/<PID>/environ | tr '\0' '\n'

# See what files the process has open
ls -la /proc/<PID>/fd/
★
CREST Exam Point: Process environment variables are a goldmine. Applications that pass credentials via environment variables (common in poorly configured Docker or systemd services) can be read by any user who can see the /proc entry. This is a real finding category: "Credentials exposed in process environment".

Part 2 - Linux Socket Enumeration
4
Socket State with ss

The ss command (socket statistics) is the modern replacement for netstat. It shows all open sockets including those listening only on localhost - services that an external nmap scan would never see.

# All listening TCP sockets with PID and process name
ss -tlnp

# All listening UDP sockets
ss -ulnp

# All TCP connections (established and listening)
ss -tnp

# All sockets (TCP + UDP + Unix sockets)
ss -tlunp

# Equivalent with netstat (if available)
netstat -tlnp 2>/dev/null

Pay special attention to services bound to 127.0.0.1 - these are only accessible from localhost. If you compromise the machine, you have direct access to these internal services that no external scan revealed.

Map PID to Process to Port

Correlate process IDs from ss with process names from ps to understand the full picture.

# ss -tlnp shows PIDs in the Users column - e.g. users:(("nginx",pid=1234,fd=6))
ss -tlnp

# Then match the PID to a full process listing
ps -p <PID> -f

# Or use lsof to get all open files/sockets for a process
lsof -p <PID> 2>/dev/null

# All network connections for a specific process name
lsof -i -n -P | grep ssh

Windows Process Enumeration
# List all running processes (Command Prompt)
tasklist

# With verbose info including memory usage
tasklist /v

# Services only
tasklist /svc

# PowerShell - detailed process list
Get-Process | Sort-Object -Property CPU -Descending

# PowerShell - processes with parent PID
Get-WmiObject Win32_Process | Select-Object ProcessId,ParentProcessId,Name,CommandLine
Windows process analysis
7
Windows Socket Enumeration
# All listening ports with owning PID
netstat -ano

# Filter to listening only
netstat -ano | findstr LISTENING

# Match PID to process name
tasklist | findstr <PID>

# PowerShell - all TCP connections with process
Get-NetTCPConnection | Where-Object State -eq Listen | Select-Object LocalPort,State,OwningProcess

# RDP port check (should be 3389 on DC01)
netstat -ano | findstr 3389
