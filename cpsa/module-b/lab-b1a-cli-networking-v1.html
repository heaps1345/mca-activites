Kali CLI Networking Fundamentals

Before you scan anything, you need to know your own machine. This lab covers the core networking commands you will use in every future lab. By the end, you will be able to find your IP address, default gateway, and DNS server - and understand what each one means.

▶ Pre-Lab Checklist

Complete these checks before starting. Raise your hand if anything is missing.

  • Kali VM is booted and you have a terminal open
  • You are logged in (default credentials: kali / kali)
  • You can open a terminal (right-click desktop, or find it in the taskbar)
Objectives
  • Find your Kali machine's IP address, subnet mask, and default gateway from the command line
  • Identify your DNS server and test name resolution
  • Use ping to test connectivity and read the TTL value in the response
  • Use traceroute to map the path to a destination
  • List active network connections and listening services on your own machine
Part 1 - Find Your Own IP Address
ℹ
On modern Kali, ifconfig still works but ip is the current standard. You will see both in real environments - know them both.
1
Show all network interfaces

This command lists every network interface on your machine - including its IP address, subnet mask, and MAC address.

ip addr
# Short form - does the same thing
ip a

You will see at least two interfaces: lo (loopback - always 127.0.0.1) and one or more named interfaces like eth0 or ens33. Your actual IP is on the named interface.

✓
Look for the line starting with inet under your network interface. The number before the slash is your IP. The number after the slash is your CIDR prefix length (e.g. /24 = 255.255.255.0).
Record your results
2
Show your routing table and default gateway

The routing table tells your machine where to send traffic. The default gateway is the router that handles everything outside your local subnet.

ip route
# Short form
ip r

Look for the line that starts with default via. The IP address after via is your default gateway - the first hop for all traffic leaving your subnet.

Record your results
3
Find your DNS server

DNS resolves hostnames to IP addresses. Without it, you cannot reach anything by name. Your configured DNS server is in /etc/resolv.conf.

cat /etc/resolv.conf

The line starting with nameserver is your DNS server. On a lab network this is often the gateway itself or a domain controller.

Record your DNS server
🎯
CREST Exam Link: In a grey-box pentest, the DNS server IP is often the domain controller. Finding it early gives you an immediate target. If the DNS server responds to LDAP on port 389, it is almost certainly running Active Directory.
Part 2 - Test Connectivity with Ping
4
Ping your default gateway

Ping sends ICMP Echo Request packets (Type 8) and waits for Echo Reply packets (Type 0). It is the simplest connectivity test. On Linux, ping runs until you stop it - use -c to send a fixed number of packets.

# Replace with your gateway IP from Step 2
ping -c 4 <YOUR_GATEWAY_IP>

Read the output carefully. Each line shows the response time in milliseconds and the TTL (Time To Live) of the reply.

ℹ
TTL and OS fingerprinting: The TTL value in a ping response is a clue about the operating system. Linux starts at 64, Windows starts at 128, Cisco devices start at 255. Each router hop reduces the TTL by 1 - so a reply of 127 means the host is Windows and one hop away.
Record your results
5
Ping a public hostname to test DNS resolution

If this works, it confirms two things: DNS is resolving names correctly, and you have outbound internet access (if the lab allows it).

ping -c 4 google.com

If you get Name or service not known, DNS is not working. If you get Network unreachable, routing is broken. If you get responses, everything is working.

What IP address did google.com resolve to?
Part 3 - Trace a Route
6
Traceroute to your gateway

Traceroute sends packets with increasing TTL values. When a packet's TTL hits zero, the router drops it and sends back an ICMP Time Exceeded message (Type 11) - revealing itself in the process. This maps the path your traffic takes.

# Replace with your gateway IP
traceroute <YOUR_GATEWAY_IP>

Each numbered line is one hop. The gateway should be hop 1. If you see * * * on a line, that router is not responding to traceroute probes - it is not necessarily down.

Record your results
🎯
CREST Exam Link: ICMP Type 11 (Time Exceeded) is what makes traceroute work. The exam may show you a packet capture and ask which ICMP type is being used. Lab B4-B covers route mapping in depth.
Part 4 - DNS Lookups
7
Resolve a hostname with nslookup

nslookup queries DNS directly. It is available on both Linux and Windows, which makes it useful for quick checks in any environment.

nslookup google.com

The output shows which DNS server answered the query and what IP address it returned. The Non-authoritative answer line means your DNS server cached this result from elsewhere - it is not the authoritative source for google.com.

Record your results
8
Query specific DNS record types with dig

dig is more powerful than nslookup. It lets you query specific record types and shows the raw DNS response. This is essential for DNS enumeration in a pentest.

# Query an A record (default)
dig google.com

# Query only the A record, short output
dig google.com A +short

# Query MX records (mail servers)
dig google.com MX

# Query NS records (name servers)
dig google.com NS
Record your results
✓
In a pentest, you will use dig axfr @<DNS_SERVER> <domain> to attempt a zone transfer. If it succeeds, you get every hostname in the domain in one query. Lab B3-A covers this.
Part 5 - What is Listening on Your Machine
9
List listening services with ss

ss shows socket statistics - which ports are open on your machine and what process is using them. This is essential for post-exploitation (Lab B14-A) but also useful now to understand what a "listening service" looks like.

# -t = TCP, -l = listening only, -n = don't resolve port names, -p = show process
ss -tlnp

# Add UDP as well
ss -tulnp

The Local Address:Port column shows what address the service is bound to. 0.0.0.0:22 means SSH is listening on all interfaces. 127.0.0.1:631 would mean a service only accessible from localhost.

Record any listening services on your Kali machine
🎯
CREST Exam Link: A service bound to 127.0.0.1 is invisible to external nmap scans. Post-exploitation, you can connect to it directly. This is a common exam question - Lab B14-A covers it in full.

Exam-Style Questions
🎯
These questions test B1 theory. Answer without looking at your notes first.
Q1

You ping a host and receive a TTL of 126 in the response. What operating system is likely running, and how many hops away is it?

Windows (default TTL 128). The TTL is 126, which is 128 minus 2, so the host is 2 hops away. Linux would start at 64 and Cisco at 255.

Q3

A service on a compromised Linux host is showing as 127.0.0.1:3306 in ss -tlnp. What does this tell you, and why is it significant post-exploitation?

Port 3306 (MySQL) is bound to loopback only - it cannot be reached from the network. External nmap scans would not detect it. Post-exploitation, with a shell on the machine, you have direct local access to the database. This is significant because databases often contain credentials, PII, or business data that demonstrate the full impact of the compromise.

Q5

You run ip a and see the following line under eth0: inet 10.1.33.14/24. What is your IP address, and what is the network address of your subnet?

Your IP address is 10.1.33.14. The /24 means the first three octets define the network, so the network address is 10.1.33.0/24. Valid host addresses on this subnet run from 10.1.33.1 to 10.1.33.254, with 10.1.33.255 as the broadcast address.
✓ Lab Complete - Key Takeaways
Before scanning anything, know your own machine. ip a gives your IP and subnet. ip r gives your gateway. /etc/resolv.conf gives your DNS server. These three pieces of information define your position on the network. TTL values in ping replies are a passive OS fingerprinting technique you will use in Lab B8-A. Everything you have done here runs on the target too - when you have a shell, the first thing you run is exactly this.
