Part 1 - ICMP Ping Sweep
1
Run a basic ICMP ping sweep

The simplest form of host discovery. Nmap sends ICMP Echo Requests (Type 8) to every address in the range and waits for replies.

# Replace with your lab subnet
nmap -sn -PE 10.1.147.0/24

The -sn flag means "ping scan only - no port scan." The -PE flag means "use ICMP Echo."

Record your results - how many hosts responded?
2
Run an aggressive multi-probe sweep

ICMP alone is often blocked. This command adds ICMP timestamp requests and a TCP probe to port 443, catching hosts that filter Echo requests.

nmap -sn -PE -PP -PS443 -PA80 10.1.147.0/24

-PP = ICMP Timestamp | -PS443 = TCP SYN to port 443 | -PA80 = TCP ACK to port 80

Did you find any additional hosts compared to Step 1?
3
Sweep with no ping - treat all hosts as up

The nuclear option. Nmap skips host discovery entirely and scans every address. Slow, but catches hosts that block all probe types.

# -Pn treats all hosts as up, -F scans top 100 ports only (faster)
nmap -Pn -F 10.1.147.0/24
⚠
This will take significantly longer. Your instructor may ask you to run this against a single IP rather than the full subnet during the lab.
When would you use -Pn in a real engagement?

Part 3 - Prioritise Your Target List

Once you have a list of live hosts, the next step is to prioritise them. Not all hosts are equal - a server with 10 open ports is a higher priority than a workstation with one.

4
Quick service scan across all discovered hosts

Run a top-100-port scan with version detection across all hosts you found. Save the output so you can reference it.

# Save output in all formats - greppable, normal, XML
nmap -sV -F --open 10.1.147.0/24 -oA syntex_sweep

--open shows only hosts with at least one open port. -oA saves three output files: .nmap, .gnmap, .xml

✓
Always save scan output with -oA. In a real engagement this is your evidence. In the exam you may be shown saved output and asked to interpret it.

Q3

You are performing a sweep and the client tells you one host definitely exists but it never appears in your results. Name two possible explanations.

ICMP is filtered by a host or network firewall (the host exists but blocks ICMP probes). The host may also be in a different subnet not included in your range, or rate limiting is dropping probes causing intermittent false negatives.

What is the purpose of the -oA flag in nmap?

Q5

A host responds to TCP SYN on port 443 but not to ICMP Echo. What does this tell you about the host's firewall configuration?

ICMP Echo is blocked (likely by a host firewall) but TCP traffic is permitted on port 443. This is the default Windows Firewall behaviour - it blocks ICMP but allows established TCP connections. The host is alive; you just cannot discover it with a ping sweep.
