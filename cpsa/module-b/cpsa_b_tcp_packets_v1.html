CPSA Module B - TCP Packets

Flags, headers, and where TCP packets are used in real attacks

01 - The TCP Header

Every TCP segment carries a fixed 20-byte header before the data payload. The fields you need to know for CPSA are:

Field Size What it does
Source Port 16 bit Sending port (ephemeral, e.g. 54321 for a client)
Destination Port 16 bit Target service port (e.g. 80, 443, 22)
Sequence Number 32 bit Tracks byte position in the stream - used to reassemble segments in order
Acknowledgement Number 32 bit Next expected byte from the other side. Only valid when ACK flag is set
Flags (Control Bits) 9 bit SYN, ACK, FIN, RST, PSH, URG, ECE, CWR, NS - control the connection state
Window Size 16 bit How many bytes the receiver can accept - used for flow control
Checksum 16 bit Error detection across the header and data

02 - TCP Flags

Flags are single bits in the TCP header. Each one signals a specific action or state. These are the six you will see constantly in CPSA labs and exam questions:

SYN - Synchronise
Bit 1
Initiates a connection. Sent in the first packet of a three-way handshake. Also used by nmap in a SYN scan (-sS) to probe ports without completing the handshake.
ACK - Acknowledge
Bit 4
Confirms receipt of data. Present in almost every packet after the initial SYN. The ACK scan (-sA) sends only ACK packets to map firewall rules.
FIN - Finish
Bit 0
Graceful connection teardown. A FIN scan (-sF) sends FIN packets to closed ports - they respond with RST, open ports stay silent.
RST - Reset
Bit 2
Abruptly terminates a connection. A closed port sends RST in response to unexpected packets. RST injection can be used to hijack or tear down sessions.
PSH - Push
Bit 3
Tells the receiver to pass buffered data to the application immediately rather than waiting for the buffer to fill. Common in interactive sessions like SSH and Telnet.
URG - Urgent
Bit 5
Marks data as urgent - the receiver processes it ahead of the queue. Rarely used in modern applications but appears in Xmas scan packets alongside FIN and PSH.

03 - The Three-Way Handshake

TCP connections always start with a three-way handshake. Understanding exactly which flags are set at each step is a core CPSA exam requirement.

Step 1 SYN Client sends SYN with a random Initial Sequence Number (ISN). No data yet - just requesting a connection.
Step 2 SYN-ACK Server responds with its own ISN (SYN) and acknowledges the client's sequence number (ACK). Both SYN and ACK bits are set.
Step 3 ACK Client acknowledges the server's ISN. Connection is now established and data transfer can begin.
CPSA exam angle: A SYN scan (-sS) sends only the first SYN and never completes the handshake. If the port is open, the target returns SYN-ACK - nmap immediately sends RST to tear it down without logging a full connection. This is why it is called a "half-open" or "stealth" scan.

04 - TCP Packets in Penetration Testing

Different nmap scan types craft TCP packets with specific flag combinations. Each produces a different response from open, closed, and filtered ports.

Scan Type Flags Sent Open Port Response Closed Port Response Use Case
-sS (SYN) SYN SYN-ACK RST Default scan - fast, low noise, no full connection
-sT (Connect) SYN then full handshake SYN-ACK then ACK RST Used when raw socket access unavailable (no root)
-sA (ACK) ACK RST (unfiltered) RST (unfiltered) Maps firewall rules - does not detect open/closed, only filtered vs unfiltered
-sF (FIN) FIN No response RST Bypasses some stateless firewalls and packet filters
-sN (Null) None (no flags) No response RST Same bypass technique as FIN - RFC-compliant closed ports send RST
-sX (Xmas) FIN + PSH + URG No response RST "Lights up like a Christmas tree" - same logic as FIN and Null
Key rule for FIN, Null and Xmas scans: These only work reliably against RFC-compliant TCP stacks. Windows systems send RST for both open and closed ports in response to these packets - making the results unreliable on Windows targets.

05 - TCP Sequence Numbers and Session Hijacking

Sequence numbers are 32-bit counters that track which bytes have been sent. Early TCP implementations used predictable ISNs (incrementing by a fixed amount) which made session hijacking trivial - an attacker who could predict the next sequence number could inject packets into an established connection.

Modern systems use cryptographically random ISNs. However sequence number analysis still matters in CPSA for:

Technique How Sequence Numbers Are Used
OS Fingerprinting Different OS stacks generate ISNs with different patterns. Nmap's -O flag analyses ISN randomness as one of several fingerprinting signals.
Wireshark Analysis Sequence and ACK numbers let you reconstruct the conversation order and spot retransmissions, resets, and injection attempts.
RST Injection Sending a RST with a valid sequence number tears down an established session - used in IDS evasion and denial of service.
