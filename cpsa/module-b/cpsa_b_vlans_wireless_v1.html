01 - What is a VLAN?

A VLAN (Virtual LAN) splits one physical network into multiple separate logical networks. Think of a hospital: one physical set of switches, but separate VLANs for clinical systems, admin, guest WiFi, and building management. Traffic on the guest VLAN cannot reach the clinical VLAN - at least, that is the idea.

The Core Idea

Each VLAN gets an ID (a number, 1-4094). Switches tag frames with their VLAN ID using the 802.1Q protocol. A switch only delivers frames to ports that belong to the same VLAN.

Native VLAN - the default VLAN on a trunk port. Frames on the native VLAN are sent untagged (no 802.1Q header). By default on Cisco kit this is VLAN 1. This matters a lot - see the double-tagging attack below.

Trunk port - a port that carries traffic for multiple VLANs (typically switch-to-switch links). Access ports carry traffic for one VLAN only.

Why pentesters care: VLAN segmentation is one of the most common security controls on internal networks - and one of the most commonly misconfigured. A client will tell you their guest WiFi is segmented from their finance servers. VLAN hopping lets you test whether that is actually true.

02 - VLAN Hopping: Double-Tagging Attack

Double-tagging exploits how switches handle the native VLAN. If you are connected to a port on the native VLAN, you can craft a packet with two 802.1Q tags stacked on top of each other. The result: your packet ends up in a VLAN you are not supposed to be in.

How it works step by step

1
Attacker is connected to a port on the native VLAN (e.g. VLAN 1)
2
Attacker crafts a frame with two 802.1Q tags - outer tag = VLAN 1 (native), inner tag = VLAN 20 (target)
3
First switch strips the outer tag (VLAN 1 = native, so it removes it) and forwards the frame on the trunk link
4
Second switch sees the inner tag (VLAN 20) and delivers the frame to VLAN 20
5
Attacker is now talking to hosts on VLAN 20 - without ever being authorised on that VLAN
Important limitation: Double-tagging is one-way. The target host's replies go back through normal routing - they do not automatically find their way back to the attacker. This means it works for attacks like sending a malicious packet, but not for a full two-way session without additional techniques.
Analogy: You put two envelopes inside each other. The outer envelope is addressed to the front desk (native VLAN). The receptionist opens it, sees it is for the internal post, and passes it on. The inner envelope is addressed to the finance director's office (VLAN 20). The internal post system delivers it there - no one checked whether you were allowed to send mail to finance.

Defence

Fix 1: Change the native VLAN to an unused VLAN ID that carries no legitimate traffic. VLAN 999, say. No real traffic uses it, so double-tagged frames targeting it go nowhere.

Fix 2: Explicitly tag the native VLAN on all trunk ports so it is treated the same as any other VLAN.

Fix 3: Never put end-user devices or attacker-reachable ports on the native VLAN.

03 - VLAN Hopping: Switch Spoofing Attack

Cisco switches use a protocol called DTP (Dynamic Trunking Protocol) to automatically negotiate trunk links between themselves. The idea is to make it easy to connect two switches together without manual configuration. The problem: if DTP is enabled on an access port and an attacker connects a device that speaks DTP, the switch will negotiate a trunk link with the attacker - handing them access to every VLAN.

What Happens

Attacker plugs in and sends DTP negotiate frames. The switch sees another "switch" and starts negotiating. Trunk link comes up. Attacker now receives traffic from all VLANs, not just the one they are plugged into.

Analogy: You walk into a building wearing a staff uniform and carrying a clipboard. The receptionist assumes you are staff and hands you a master key instead of a visitor pass. You now have access to every room.

Defence

Fix 1: Disable DTP on all access ports: switchport nonegotiate

Fix 2: Hardcode access ports as access mode: switchport mode access

Fix 3: Hardcode trunk ports explicitly rather than relying on auto-negotiation.
CREST exam angle: Know both attacks by name and mechanism. Double-tagging requires the attacker to be on the native VLAN and exploits 802.1Q tag stripping. Switch spoofing exploits DTP auto-negotiation. Know the defences for each.

04 - Wireless Encryption: What's Broken and What Isn't

Wireless security has had a rough history. Several standards that were once considered acceptable are now trivially broken. You need to know exactly what is broken, why, and what tool breaks it.

WEP
BROKEN - DO NOT USE
RC4 stream cipher with weak, reused IVs. Crackable in minutes with aircrack-ng. No modern use case.
WPA / TKIP
WEAK - AVOID
Improvement on WEP but has design flaws in TKIP. Deprecated. Should not be in use.
WPA2-PSK
VULNERABLE TO WEAK PASSWORDS
Secure protocol but vulnerable to offline dictionary attack if a weak passphrase is used. Capture the 4-way handshake, crack offline with hashcat.
WPA2-Enterprise
SECURE (IF CONFIGURED CORRECTLY)
Uses 802.1X and RADIUS - each user gets individual credentials. No shared passphrase to crack.
WPA3 / SAE
SECURE
Simultaneous Authentication of Equals replaces the vulnerable 4-way handshake. Offline cracking is not possible even with a weak password.
WPS
BROKEN - DISABLE IT
8-digit PIN split as two independent 4-digit halves. Only 11,000 combinations needed. Reaver/Bully brute-force it in hours.

05 - Breaking WEP

WEP uses the RC4 stream cipher. The problem is not RC4 itself - it is how WEP uses it. WEP generates a 24-bit Initialisation Vector (IV) and prepends it to the key before encrypting. 24 bits gives only about 16 million possible IVs. On a busy network, IVs start repeating within minutes. When you have enough packets with repeated IVs, you can mathematically recover the key - no brute force needed.

The Attack Flow

1. Put your wireless adapter into monitor mode

2. Capture packets on the target network - you need enough IVs (typically 20,000-40,000 unique IVs)

3. Speed up IV collection by injecting ARP packets (forces the AP to respond repeatedly, generating more IVs)

4. Run aircrack-ng against the captured file - it statistically recovers the WEP key

Still found in the wild: Legacy IoT devices, old access points, industrial equipment, and some home routers still run WEP. Finding WEP on an engagement is an automatic critical finding. Tool: aircrack-ng (pre-installed in Kali).

06 - Breaking WPA2-PSK

WPA2-PSK itself is not broken - but if the passphrase is weak, it can be cracked offline after capturing the authentication handshake. The key exchange happens in a 4-step process (the 4-way handshake) when a client connects to the access point. That handshake contains enough information to verify a passphrase guess - without needing to reconnect to the network.

The Attack Flow

1. Put your adapter into monitor mode on the target channel

2. Capture traffic and wait for a client to connect - or send a deauthentication frame to force a client to reconnect

3. Capture the 4-way handshake

4. Take the capture file offline and run hashcat with a wordlist (rockyou.txt is the classic starting point)

5. If the passphrase is in the wordlist or guessable, hashcat recovers it

Key point: You are not attacking the encryption - you are doing an offline dictionary attack against the passphrase. A strong random passphrase (20+ characters) makes this attack impractical even with the full rockyou.txt wordlist. A weak passphrase like "password123" falls in seconds.

07 - Breaking WPS

WPS (Wi-Fi Protected Setup) was designed to make it easy to add devices to a network without typing a long passphrase - just enter an 8-digit PIN. The problem is a catastrophic design flaw: the router validates the first 4 digits of the PIN separately from the last 4 digits. This means instead of 100,000,000 combinations (10^8), there are only about 11,000 combinations to try (10^4 + 10^4).

Why 11,000?

The PIN is 8 digits. The last digit is a checksum (calculated, not random). So there are 7 real digits.

The router checks digits 1-4 first, then digits 5-7. That means: 10,000 combinations for the first half + 1,000 for the second half = ~11,000 total guesses needed. A brute-force that would take years becomes a matter of hours.

Tools: Reaver and Bully both exploit this. Even if WPS is "disabled" in the UI, some routers still respond to WPS handshakes. Always test it. Finding WPS enabled on an engagement is a critical finding.
