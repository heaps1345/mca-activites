Google Hacking and Search Engine Reconnaissance

Search engines index far more than intended public content. Using advanced operators - known as "Google dorks" - a skilled tester can find exposed files, login panels, configuration data, and indexed directories that the target never meant to share.

🔎 Pre-Flight Checks

No VMs required. All reconnaissance uses public search engines and browser only.

  • Firefox or Chromium browser open
  • Google Search (google.com) accessible
🚀

Away you go!

All pre-flight checks complete. You are ready to start the lab.

Scenario

During passive recon on Syntex Solutions Ltd, you have identified their primary domain. Before any active scanning, use Google dorks and the Google Hacking Database to discover exposed content, sensitive files, and information disclosure issues indexed by search engines.

Learning Objectives
  • Use core Google dork operators to narrow search results
  • Combine operators to build targeted reconnaissance queries
  • Use the Google Hacking Database (GHDB) as a dork reference
  • Identify the types of sensitive content commonly found via dorking
  • Understand the legal and ethical boundaries of Google hacking
Part 1 - Core Dork Operators

Google's advanced operators let you filter search results to specific domains, file types, URL patterns, and page content. Learning these operators is essential for passive OSINT.

site:
Restrict results to one domain
site:example.com
filetype: / ext:
Find specific file types
site:example.com filetype:pdf
inurl:
Find URLs containing a keyword
site:example.com inurl:admin
intitle:
Find pages with keyword in title
intitle:"index of" site:example.com
intext:
Find pages containing body text
intext:"password" site:example.com
cache:
View Google's cached copy
cache:example.com/login
-
Exclude a term from results
site:example.com -www
" "
Exact phrase match
"admin panel" site:example.com
⚠
Legal boundary: Viewing Google search results and Google's cached pages is passive recon - no direct connection to the target. Accessing a live page you found via dorking is a direct connection. Know where the line is before any engagement.

Enumerate subdomains via site: operator

The site: operator without www reveals all subdomains Google has indexed for a target. This is passive enumeration with no direct target contact.

2
Find exposed file types

Documents, spreadsheets, and config files are frequently indexed by accident. These often contain internal data, employee names, or system information.

Find PDFs (often contain internal document metadata):
site:bbc.co.uk filetype:pdf

Find Excel spreadsheets:
site:bbc.co.uk filetype:xlsx OR filetype:xls

Find exposed config files (dangerous on real targets):
site:example.com ext:cfg OR ext:conf OR ext:ini OR ext:env

Find text/log files:
site:example.com ext:txt OR ext:log
🎯
CREST Exam Focus: Know these file types by heart - .pdf, .xls, .xlsx, .doc, .docx, .txt, .bak, .sql, .cfg, .conf, .env, .log. The exam may ask which file types are most valuable in passive recon.

3
Find login panels and admin interfaces

Admin panels and login forms exposed to the internet are high-value targets. Google often indexes them even when not linked from the main site.

Find admin panels:
site:example.com inurl:admin
site:example.com inurl:login
site:example.com inurl:wp-admin

Find pages with login in the title:
site:example.com intitle:"login"
site:example.com intitle:"admin panel"
site:example.com intitle:"administrator"

Find phpMyAdmin (database management tool):
inurl:phpmyadmin/index.php site:example.com

4
Find open directory listings

Apache and IIS web servers show directory listings when index.html is absent. These expose the entire file structure of that directory.

Classic open directory dork:
intitle:"index of" site:example.com

Find specific exposed directories:
intitle:"index of" "backup" site:example.com
intitle:"index of" "uploads" site:example.com
intitle:"index of" ".git" site:example.com
ℹ
An exposed .git directory is critical severity - it allows an attacker to reconstruct the entire source code of the application including all previous commits, credentials hardcoded in history, and internal architecture.
Part 3 - Google Hacking Database (GHDB)
5
Use GHDB for pre-built dork queries

The Google Hacking Database at exploit-db.com/google-hacking-database is a community-maintained library of thousands of dork queries, categorised by type.

GHDB categories to know:
- Files containing passwords
- Sensitive directories
- Pages containing login portals
- Various online devices (webcams, printers)
- Vulnerable servers
- Error messages
- Files containing usernames
✓
On a real engagement, open GHDB, filter by "Files Containing Passwords" or "Sensitive Directories", copy the dork, and add site:target.com to restrict it to your target. This takes minutes and can find critical findings immediately.

Q3

What does the dork intitle:"index of" look for, and why is it significant?

It finds web pages with "index of" in the title, which is the default heading Apache and IIS use when serving a directory listing. Directory listings expose the full file tree of that folder - you can see and download every file without needing to know URLs in advance. They are significant because they may expose backup files, configuration files, source code, database dumps, and other sensitive content that was never intended to be public.
Q4

You find an exposed .git directory on a target. What is the significance and what does it allow an attacker to do?

An exposed .git directory is a critical finding. Git stores the entire version history of the repository locally. By downloading the .git directory, an attacker can reconstruct the full source code of the application using `git checkout`. This can reveal: hardcoded credentials or API keys in old commits (even if removed later), internal architecture and database schemas, commented-out debug code, and the full application logic for finding vulnerabilities. The tool `git-dumper` automates recovery from exposed .git directories.

★
Lab Complete - Key Takeaways: Google hacking is a powerful passive technique requiring no tools beyond a browser. The site:, filetype:, inurl:, intitle:, intext: and cache: operators are your core toolkit. Directory listings (intitle:"index of") and exposed admin panels are the highest-value quick wins. The GHDB provides thousands of pre-built dorks. Always clarify with the client whether passive OSINT using public search engines is in scope - it usually is, but confirm.
