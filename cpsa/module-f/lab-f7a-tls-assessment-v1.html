Lab Overview

TLS (Transport Layer Security) assessment is a standard component of any CPSA infrastructure engagement. This lab covers SSL/TLS protocol version identification, cipher suite enumeration, certificate analysis, and identification of weak configurations. SYNTEX-LNX01 is intentionally configured with legacy TLS 1.0/1.1 support and weak cipher suites for this exercise.

⚠️
TLS 1.0 and TLS 1.1 are deprecated. PCI DSS 3.2+ requires TLS 1.2 minimum. NCSC guidelines require TLS 1.2 or 1.3 for all new deployments. Finding TLS 1.0/1.1 support is a reportable finding on any CPSA engagement.
Learning Objectives
  • 1Enumerate supported TLS protocol versions
  • 2Identify weak and deprecated cipher suites
  • 3Analyse the server certificate (validity, key size, issuer)
  • 4Check for known TLS vulnerabilities (BEAST, POODLE, DROWN)
  • 5Document findings with remediation recommendations
Tools Required
sslscan testssl.sh nmap openssl
Lab Steps
1
sslscan - Protocol Version Enumeration
▶

sslscan connects to the target and probes for supported SSL/TLS protocol versions and cipher suites.

sslscan <TARGET_IP>:443

# Key output to look for:
SSL/TLS Protocols:
SSLv2     disabled
SSLv3     disabled
TLSv1.0   enabled
TLSv1.1   enabled
TLSv1.2   enabled
TLSv1.3   disabled

Certificate Information:
Subject:  CN=syntex-lnx01.syntex.local
Issuer:   CN=syntex-lnx01.syntex.local (Self-signed)
RSA Key Strength: 2048 bits
Signature Algorithm: sha256WithRSAEncryption
Not valid before: ...
Not valid after:  ... (3650 days)
🚨
TLS 1.0 enabled - this is vulnerable to the BEAST attack (CVE-2011-3389). TLS 1.1 enabled - deprecated since RFC 8996 (March 2021). Both should be disabled and replaced with TLS 1.2/1.3 only.
2
Cipher Suite Analysis
▶

Review the cipher suites sslscan reports. Look for weak key exchange, authentication, and bulk encryption algorithms.

# sslscan output - cipher suites section
Preferred TLSv1.0  128 bits  ECDHE-RSA-AES128-SHA
Accepted  TLSv1.0  256 bits  ECDHE-RSA-AES256-SHA
Accepted  TLSv1.0  128 bits  AES128-SHA
Accepted  TLSv1.0  256 bits  AES256-SHA
Accepted  TLSv1.0  168 bits  DES-CBC3-SHA      (3DES - weak)
Preferred TLSv1.1  128 bits  ECDHE-RSA-AES128-SHA
Preferred TLSv1.2  256 bits  ECDHE-RSA-AES256-GCM-SHA384
Cipher ComponentWeak Indicators
Key ExchangeRSA (no PFS), EXPORT, anon (NULL)
AuthenticationNULL, anon, EXPORT
Bulk EncryptionDES, 3DES, RC4, EXPORT (40/56-bit), NULL
MACMD5, SHA1 (in CBC mode - BEAST target)
ℹ️
The SSLCipherSuite configured on this server intentionally allows weak cipher suites for lab purposes. The recommended production cipher string for Apache is: ECDH+AESGCM:DH+AESGCM:ECDH+AES256:DH+AES256:ECDH+AES128:DH+AES:!aNULL:!MD5:!DSS
3
Certificate Analysis with OpenSSL
▶

Examine the certificate in detail. The self-signed certificate has several reportable issues.

openssl s_client -connect <TARGET_IP>:443 </dev/null 2>/dev/null | openssl x509 -noout -text
# Key fields to extract:
openssl s_client -connect <TARGET_IP>:443 </dev/null 2>/dev/null | openssl x509 -noout -subject -issuer -dates -fingerprint

subject=C=GB, ST=England, L=London, O=Syntex Solutions Ltd, CN=syntex-lnx01.syntex.local
issuer=C=GB, ST=England, L=London, O=Syntex Solutions Ltd, CN=syntex-lnx01.syntex.local
notBefore=...
notAfter=... +10 years
SHA1 Fingerprint=...
⚠️
The certificate is self-signed (issuer = subject). Self-signed certificates are not trusted by browsers or operating systems and cannot be validated by clients, leaving them vulnerable to MITM attacks. A trusted CA-signed certificate is required for production use.
# Check key size
openssl s_client -connect <TARGET_IP>:443 </dev/null 2>/dev/null | openssl x509 -noout -text | grep -A2 "Public Key"

Public Key Algorithm: rsaEncryption
    RSA Public-Key: (2048 bit)
4
testssl.sh - Comprehensive TLS Testing
▶

testssl.sh provides a more comprehensive assessment including named vulnerability checks.

# Full assessment
testssl.sh <TARGET_IP>:443

# If testssl.sh not installed:
git clone --depth 1 https://github.com/drwetter/testssl.sh.git /opt/testssl
/opt/testssl/testssl.sh <TARGET_IP>:443
# Check specific vulnerabilities only
testssl.sh --vulnerable <TARGET_IP>:443
ℹ️
testssl.sh checks for BEAST, BREACH, POODLE, FREAK, Logjam, SWEET32, ROBOT, LUCKY13, and DROWN among others. On a real engagement, run both sslscan and testssl.sh - they occasionally differ in what they detect.
5
Nmap SSL Scripts
▶

Nmap provides SSL-specific scripts that integrate with your port scan output.

nmap -p 443 --script ssl-enum-ciphers,ssl-cert,ssl-dh-params <TARGET_IP>
