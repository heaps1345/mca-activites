Lab Overview

SMB (Server Message Block) is a network file sharing protocol. This lab covers SMB service enumeration against a Samba host running on Linux, including protocol version identification, guest access testing, share enumeration, and accessing unprotected network shares. You will recover sensitive data from an exposed finance share and identify legacy protocol risks.

🪟 Windows vs Linux Context

Null sessions (unauthenticated IPC$ access) are primarily a Windows Active Directory phenomenon, where they historically allowed full SAM database enumeration. On Linux Samba hosts, the equivalent is guest access - shares configured with guest ok = yes and map to guest = Bad User. Both are covered by CPSA syllabus area F3. When you encounter Windows targets (SYNTEX-WIN01), you will apply null session techniques in their full AD context.

Lab Steps
1
SMB Service Discovery and Version Detection
▶

Start with Nmap to identify SMB ports and enumerate protocol versions. SMB runs on TCP 139 (NetBIOS) and TCP 445 (direct).

nmap -p 139,445 -sV --script smb-protocols,smb-security-mode,smb2-security-mode <TARGET_IP>

# Look for:
PORT    STATE SERVICE     VERSION
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X
445/tcp open  microsoft-ds Samba smbd 4.11.6

Host script results:
| smb-protocols:
|   dialects:
|     NT LM 0.12 (SMBv1) dialects supported
|     2.0.2
|     2.1
|_    3.0
| smb-security-mode:
|   account_used: guest
|   authentication_level: user
|   challenge_response: supported
|_  message_signing: disabled
⚠️
SMBv1 support is a significant finding. SMBv1 is the protocol exploited by EternalBlue (MS17-010 / WannaCry). Even on a patched host, SMBv1 represents an unnecessary attack surface that should be disabled.
2
Share Enumeration with enum4linux
▶

enum4linux wraps several SMB enumeration tools into a single script. Run it without credentials to test guest/anonymous access.

enum4linux -a <TARGET_IP> 2>/dev/null | tee /tmp/enum4linux.txt

# Key output sections:
===========================
|    Share Enumeration    |
===========================
        Sharename       Type      Comment
        ---------       ----      -------
        public          Disk
        finance         Disk
        it              Disk
        IPC$            IPC       IPC Service

[+] Attempting to map shares on <TARGET_IP>
//<TARGET_IP>/public       Mapping: OK, Listing: OK
//<TARGET_IP>/finance      Mapping: OK, Listing: OK
//<TARGET_IP>/it           Mapping: OK, Listing: OK
# Also try enum4linux-ng for a more modern version
enum4linux-ng -A <TARGET_IP>
ℹ️
The target is configured with map to guest = Bad User - any invalid or blank username authenticates as the guest account. This is the Samba equivalent of a null session on Windows.
3
Share Access with smbclient
▶

Connect to shares directly with smbclient. Use an empty password to test guest access.

# List shares without credentials
smbclient -L //<TARGET_IP> -N

# Connect to the finance share
smbclient //<TARGET_IP>/finance -N

# Once in the SMB shell:
smb: \> ls
smb: \> get Q3_Budget_2024.txt /tmp/Q3_Budget_2024.txt
smb: \> exit
# View the retrieved file
cat /tmp/Q3_Budget_2024.txt

SYNTEX SOLUTIONS - Q3 FINANCIAL SUMMARY - CONFIDENTIAL
Revenue: £2.4M
Staff costs: £1.1M
IT Budget remaining: £45,000
Finance Director: sarah.jones@syntex.local
Password reminder: Syntex2024! (change after reading)
🚨
You have recovered a cleartext credential (Syntex2024!) from an unauthenticated share access. This credential should be tested against other services in scope (SSH, web admin, etc.) and documented as a critical finding.
4
smbmap for Rapid Share Mapping
▶

smbmap quickly maps all shares and their permissions - useful for quickly identifying readable/writable shares.

# Anonymous access
smbmap -H <TARGET_IP>

    Disk              Permissions     Comment
    ----              -----------     -------
    public            READ, WRITE
    finance           READ, WRITE
    it                READ, WRITE
    IPC$              NO ACCESS       IPC Service

# Recursive listing of finance share
smbmap -H <TARGET_IP> -r finance
# Test recovered credential against all shares
smbmap -H <TARGET_IP> -u 'admin' -p 'Syntex2024!'
5
Nmap SMB Vulnerability Scripts
▶

Run Nmap's SMB vulnerability scripts to check for known exploitable conditions.

nmap -p 445 --script smb-vuln* <TARGET_IP>

# Check specifically for EternalBlue
nmap -p 445 --script smb-vuln-ms17-010 <TARGET_IP>

# Check for signing
nmap -p 445 --script smb-security-mode <TARGET_IP>
ℹ️
SMB signing disabled allows relay attacks (NTLM relay / Responder). Even if EternalBlue is not present, disabled SMB signing is a reportable finding on any CPSA engagement.
6
Windows Context - Null Sessions
▶

Understanding null sessions is essential for CPSA. They are primarily a Windows/Active Directory phenomenon.

ℹ️
Null Session (Windows): An unauthenticated connection to the IPC$ share on a Windows host. On legacy systems (pre-Server 2003 SP1), null sessions allowed full enumeration of users, groups, shares, and the SAM database via the NetBIOS/SMB protocol. Windows Server 2003 SP1+ restricts this by default, but misconfigurations in AD environments still expose null session access on domain controllers and legacy servers.

Commands you will use against Windows targets:

# Windows null session - connect to IPC$ with no creds
smbclient //<WINDOWS_TARGET>/IPC$ -N

# enum4linux against Windows AD host
enum4linux -a <WINDOWS_TARGET>

# rpcclient null session
rpcclient -U "" -N <WINDOWS_TARGET>
rpcclient $> enumdomusers
rpcclient $> enumdomgroups
💡
You will apply these techniques against SYNTEX-WIN01 in the Windows assessment module. The principles are the same - unauthenticated SMB access enabling user/group enumeration - but the Windows implementation via IPC$ and RPC calls is more powerful than Linux guest shares.
