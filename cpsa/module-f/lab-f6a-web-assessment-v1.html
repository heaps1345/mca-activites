Lab Overview

Web services are present on almost every infrastructure engagement. This lab covers web server fingerprinting, banner analysis, information disclosure via misconfiguration (directory listing, phpinfo), and systematic credential harvesting from exposed web content. These are reconnaissance techniques performed before any active exploitation.

ℹ️
This lab focuses on passive web enumeration - reading what the server exposes without active exploitation. Many CPSA findings in web assessments come from server misconfiguration rather than application vulnerabilities.
Learning Objectives
  • 1Fingerprint the web server using banner grabbing and Nmap scripts
  • 2Identify information disclosure via directory listing
  • 3Extract system configuration from phpinfo()
  • 4Harvest credentials from exposed backup and development files
  • 5Perform directory brute-forcing with gobuster/dirbuster
Tools Required
nmap curl gobuster nikto whatweb
Lab Steps
1
Web Server Fingerprinting
▶

Identify the web server software, version, and technologies before browsing to the site.

# Banner grab via curl
curl -I http://<TARGET_IP>/

HTTP/1.1 200 OK
Date: ...
Server: Apache/2.4.41 (Ubuntu)
X-Powered-By: PHP/7.4.3
Content-Type: text/html; charset=UTF-8
# Nmap HTTP scripts
nmap -p 80,443 -sV --script http-headers,http-server-header,http-title <TARGET_IP>

# WhatWeb for technology detection
whatweb http://<TARGET_IP>
💡
Server: Apache/2.4.41 (Ubuntu) and X-Powered-By: PHP/7.4.3 are both information disclosure findings. Production servers should suppress version information. Note these for your report - the CPSA recommendation is ServerTokens Prod for Apache.
2
Directory Listing Discovery
▶

The home page links to several directories. Browse to them directly to check for directory listing.

# Check each directory from the homepage links
curl http://<TARGET_IP>/backup/
curl http://<TARGET_IP>/dev/
curl http://<TARGET_IP>/admin/
curl http://<TARGET_IP>/config/
# Directory listing gives you file names without needing to guess
Index of /backup
[ICO] Name       Last modified   Size  Description
[TXT] config.bak 2024-10-18     350

[PARENTDIR] Parent Directory
🚨
Directory listing (Apache Options Indexes) exposes the full directory tree to unauthenticated users. This is a critical misconfiguration - it allows attackers to discover files that were never intended to be publicly accessible.
3
Credential Harvesting from Exposed Files
▶

Retrieve the files exposed by directory listing. Both /backup/ and /dev/ contain plaintext credentials.

curl http://<TARGET_IP>/backup/config.bak

# Syntex Application Config - BACKUP COPY
DB_HOST=localhost
DB_NAME=syntexdb
DB_USER=syntex_app
DB_PASS=AppPass2024!
ADMIN_USER=admin
ADMIN_PASS=admin123
SECRET_KEY=syntex_secret_2024
curl http://<TARGET_IP>/dev/notes.txt

Dev Notes - NOT FOR PRODUCTION
TODO: remove hardcoded creds before go-live
admin / admin123
jsmith / Password1
DB: syntex_app / AppPass2024!
⚠️
You now have three credential sets from web enumeration alone. Add these to your credential list and test against SSH, FTP, the database, and any admin panels in scope.
4
phpinfo() Analysis
▶

The phpinfo() page reveals detailed server configuration - PHP version, loaded modules, server paths, and environment variables.

curl http://<TARGET_IP>/phpinfo.php | grep -i "Server\|PHP Version\|document_root\|extension\|disable_functions"

Key information to note from phpinfo():

FieldWhy It Matters
PHP VersionCheck for known CVEs against this version
Document RootAbsolute path helps if LFI/directory traversal found later
disable_functionsEmpty = all PHP functions enabled, including system()
allow_url_fopenOn = remote file inclusion possible
Server APIApache2Handler confirms mod_php, not FPM
Loaded ExtensionsMySQLi, curl etc. - database connectivity confirmed
🚨
phpinfo() is a critical information disclosure finding. It should never be accessible on a production system. It provides enough detail to significantly assist exploitation of other vulnerabilities.
5
Directory Brute-Forcing
▶

Even with directory listing, gobuster can find hidden directories and files not linked from the main page.

gobuster dir -u http://<TARGET_IP> -w /usr/share/wordlists/dirb/common.txt -x php,txt,bak,conf -t 50
# Or with dirsearch
dirsearch -u http://<TARGET_IP> -e php,txt,bak,conf
# Nikto for vulnerability scanning and additional disclosure
nikto -h http://<TARGET_IP>
💡
Nikto will flag the directory listing, missing security headers, phpinfo, and Apache version disclosure automatically. Its output maps well to CPSA finding categories. Always run it as part of web service assessment.
6

▶

Check for missing HTTP security headers - a common CPSA finding category.

curl -I http://<TARGET_IP>/ | grep -i "x-frame\|x-content\|strict-transport\|content-security\|x-xss"
