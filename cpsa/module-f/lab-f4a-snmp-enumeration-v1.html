Lab Overview

SNMP (Simple Network Management Protocol) is a UDP-based protocol used for network device management. Misconfigured SNMP services expose significant system information including running processes, network interfaces, installed software, and user accounts. This lab covers community string enumeration, MIB walking, and extracting actionable intelligence from SNMP responses.

ℹ️
SNMP v1 and v2c use community strings as cleartext passwords. Default strings (public, private) are extremely common in production environments. CREST assessors are expected to identify and exploit weak community strings as part of host discovery and enumeration.
Learning Objectives
  • 1Identify SNMP services using Nmap UDP scanning
  • 2Enumerate valid community strings using onesixtyone
  • 3Walk the full MIB tree using snmpwalk
  • 4Extract system information, running processes, and network interfaces
  • 5Document findings to CPSA reporting standard

Lab Steps
1
SNMP Service Discovery
▶

SNMP runs on UDP port 161. Standard TCP scans miss it - you must explicitly scan UDP. Note that UDP scanning is slower than TCP and requires root/sudo.

sudo nmap -sU -p 161 --open <TARGET_IP>
# Quick UDP scan for SNMP only

# Expected output:
PORT    STATE SERVICE
161/udp open  snmp
sudo nmap -sU -p 161 -sV --script snmp-info <TARGET_IP>
# Version detection + default script
💡
If -sU is slow, add --min-rate 1000 to speed it up. UDP scanning sends packets and waits for ICMP port-unreachable responses - open ports often don't respond at all.
2
Community String Enumeration
▶

Community strings act as cleartext passwords for SNMP access. Use onesixtyone to brute-force common strings.

# Create a community string wordlist
cat > /tmp/communities.txt << 'EOF'
public
private
internal
community
manager
admin
snmp
monitor
syntex
network
cisco
router
EOF
onesixtyone -c /tmp/communities.txt <TARGET_IP>

# Expected output:
Scanning 1 hosts, 12 communities
<TARGET_IP> [public] Linux syntex-lnx01 5.4.0-150-generic #167-Ubuntu...
<TARGET_IP> [private] Linux syntex-lnx01 5.4.0-150-generic...
<TARGET_IP> [internal] Linux syntex-lnx01 5.4.0-150-generic...
<TARGET_IP> [syntex] Linux syntex-lnx01 5.4.0-150-generic...
⚠️
Document ALL valid community strings found. Read-write community strings (rwcommunity) allow configuration changes to the device - a critical finding on any engagement.
3
MIB Walking - System Information
▶

Walk the MIB tree to extract system information. Start with the system MIB (OID 1.3.6.1.2.1.1) which is always accessible.

# Walk the system MIB
snmpwalk -v2c -c public <TARGET_IP> 1.3.6.1.2.1.1

# Look for:
SNMPv2-MIB::sysDescr.0 = STRING: Linux syntex-lnx01 5.4.0-150-generic
SNMPv2-MIB::sysObjectID.0 = OID: NET-SNMP-MIB::netSnmpAgentOIDs.10
SNMPv2-MIB::sysContact.0 = STRING: admin@syntex.local
SNMPv2-MIB::sysName.0 = STRING: SYNTEX-LNX01
SNMPv2-MIB::sysLocation.0 = STRING: Syntex HQ, London
# Full MIB walk - pipe to file for analysis
snmpwalk -v2c -c public <TARGET_IP> . > /tmp/snmp_full.txt 2>&1
wc -l /tmp/snmp_full.txt
ℹ️
Key OID branches to walk: 1.3.6.1.2.1.25.4.2 (running processes), 1.3.6.1.2.1.2.2 (network interfaces), 1.3.6.1.2.1.25.6.3 (installed software), 1.3.6.1.4.1.77.1.2.25 (user accounts on Windows).
4
Extract Running Processes and Network Interfaces
▶

Use targeted OID queries to extract specific system data that informs the wider assessment.

# Running processes (hrSWRunName)
snmpwalk -v2c -c public <TARGET_IP> 1.3.6.1.2.1.25.4.2.1.2

# Network interfaces
snmpwalk -v2c -c public <TARGET_IP> 1.3.6.1.2.1.2.2.1.2

# IP addresses
snmpwalk -v2c -c public <TARGET_IP> 1.3.6.1.2.1.4.20.1.1

# Installed software
snmpwalk -v2c -c public <TARGET_IP> 1.3.6.1.2.1.25.6.3.1.2
# snmp-check gives a nicely formatted summary
snmp-check -c public -v 2c <TARGET_IP>
💡
Running processes revealed via SNMP can identify internal tooling, backup agents, monitoring software, and database services that weren't visible in the port scan. Cross-reference with your open port list.
5
Read-Write Community String Test
▶

The internal community string is configured as read-write (rwcommunity). Verify this and demonstrate the impact.

# Verify rwcommunity by attempting to read system name
snmpget -v2c -c internal <TARGET_IP> 1.3.6.1.2.1.1.5.0
SNMPv2-MIB::sysName.0 = STRING: SYNTEX-LNX01

# A read-write string could allow config changes - document but do NOT modify
# On a real engagement, changing sysName or routing tables is out of scope
🚨
Scope boundary: Never use a read-write community string to modify target configuration during an assessment. Demonstrating that the string grants write access (by reading with it) is sufficient evidence. Note this finding and confirm with your engagement lead before attempting any writes.
6
Nmap SNMP Scripts
▶

Nmap includes several SNMP NSE scripts that automate common enumeration tasks.

sudo nmap -sU -p 161 --script snmp-brute,snmp-info,snmp-interfaces,snmp-processes,snmp-sysdescr <TARGET_IP>
# snmp-brute with custom wordlist
sudo nmap -sU -p 161 --script snmp-brute --script-args snmp-brute.communitiesdb=/tmp/communities.txt <TARGET_IP>
