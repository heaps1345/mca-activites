Lab Objectives

  • Enumerate logged-in users via rusers and finger daemon (port 79)
  • Extract the full user list from SMTP using VRFY and RCPT TO fallback
  • Banner-grab FTP, SMTP, and SSH to record daemon versions
  • Document findings with evidence in CPSA report format
1
Verify Connectivity to SYNTEX-LNX01
▾

Before beginning enumeration confirm that SYNTEX-LNX01 is reachable and identify which ports are responding.

Command

nmap -sV -p 21,22,25,79,111,513,514 10.10.10.50

Expected Results

PortServiceSignificance
21FTPFile transfer - check anonymous access (F3)
22SSHBanner grab reveals version
25SMTPSendmail - VRFY/EXPN enumeration (F4)
79fingerUser enumeration direct from /etc/passwd
111rpcbindRPC portmapper - NFS and R* services
513login / rusersRemote user listing
Record the full nmap output. These port states are evidence. Closed ports are evidence too - note them as "not observed".

Mark complete when done:

2
rusers and rwho - RPC User Listing
▾

rusers queries the rusersd RPC service on port 513. It returns currently logged-in users with idle time, terminal, and login time. If rusersd is running, this dumps a complete active session list.

Commands

rusers -al 10.10.10.50
rusers 10.10.10.0/24

Interpreting Output

ColumnMeaning
UsernameValid system account - add to your user list
TTY/ptsInteractive login (pts/0 = SSH, console = physical)
Idle timeHow long since activity - active sessions are higher value targets

If rusers returns no data

# rusersd may not be running; try rpcinfo to confirm
rpcinfo -p 10.10.10.50 | grep rusers
No response from rusers is itself a finding - note that the service is not exposed. Do not skip documentation of a check just because it returned nothing.
3
finger Daemon - Port 79 Enumeration
▾

finger reads directly from /etc/passwd and returns the full user list including home directory, shell, and .plan file. A single query to @host returns all users at once.

Commands

# Banner grab first
nc -vn 10.10.10.50 79

# List all users
finger @10.10.10.50

# Query specific accounts
finger root@10.10.10.50
finger jsmith@10.10.10.50

What to Document

FieldIntelligence Value
Login nameConfirmed valid usernames for subsequent attacks
Home directoryReveals mount points and filesystem layout
Shell/sbin/nologin = service account; /bin/bash = interactive
.plan / .projectMay contain role info, contact details, internal project names
Last login timeIdentifies active vs. dormant accounts

Classify service accounts separately from interactive accounts in your report. www-data and postgres expand the attack surface differently than jsmith.
4
SMTP VRFY Enumeration
▾

SMTP VRFY validates whether a username exists on the mail system. On Sendmail, VRFY reads the local alias database and returns a 250 response for valid users. This is manual but produces precise, undeniable evidence.

Manual Enumeration

telnet 10.10.10.50 25

HELO attacker
VRFY root
VRFY jsmith
VRFY admin
VRFY testuser
QUIT

Response Codes

CodeMeaning
250User exists - add to confirmed list
251User not local but will forward - still a valid username
252Cannot VRFY but will attempt delivery - treat as valid
550User unknown - not a valid account
502VRFY disabled - fall back to RCPT TO

Automated Enumeration

# VRFY mode
smtp-user-enum -M VRFY \
  -U /usr/share/seclists/Usernames/top-usernames-shortlist.txt \
  -t 10.10.10.50

# RCPT TO fallback if VRFY disabled
smtp-user-enum -M RCPT \
  -U /usr/share/seclists/Usernames/top-usernames-shortlist.txt \
  -t 10.10.10.50 \
  -f pentest@syntex.local
RCPT TO mode generates mail delivery attempts. Ensure your rules of engagement permit this before running automated RCPT TO against a production mail server.
5
Banner Grabbing - FTP, SMTP, SSH
▾

Banner grabbing is pre-authentication intelligence. Daemon version strings feed directly into vulnerability research and are required in the CPSA report as evidence.

FTP Banner

nc -vn 10.10.10.50 21
# Expected: 220 SYNTEX-LNX01 FTP server (Version wu-2.6.2) ready

SMTP Banner

nc -vn 10.10.10.50 25
# Expected: 220 mail.syntex.local ESMTP Sendmail 8.9.3/8.9.3; Mon, 21 Oct 2024

SSH Banner

nc -vn 10.10.10.50 22
# Expected: SSH-2.0-OpenSSH_7.4p1 Debian-10+deb9u7
SSH banner version strings are compared against CVE feeds in F2. Record the exact string including sub-version. OpenSSH_7.4p1 and OpenSSH_7.4p2 have different CVE exposure.

Save All Banners

# Capture all three in one script run
for port in 21 22 25; do
  echo "=== Port $port ===" >> banners.txt
  nc -vn -w 3 10.10.10.50 $port >> banners.txt 2>&1
  echo "" >> banners.txt
done
cat banners.txt
6
Compile Findings and CPSA Evidence
▾

Consolidate all usernames identified across rusers, finger, and SMTP into a single list. This becomes the attack surface for subsequent lab exercises.

User List Template

# SYNTEX-LNX01 - Confirmed User Accounts (CPSA Evidence F1)
# Enumerated: 2024-10-21 | Tester: [your name] | Method: rusers/finger/SMTP VRFY

root              # superuser - priority target
jsmith            # interactive - VRFY confirmed
www-data          # web service account
postgres          # database service account
syslog            # logging daemon - service account

Finding Classification

FindingSeverityEvidence Required
finger daemon exposed publiclyMediumfinger @host output + banner grab
SMTP VRFY enabledMediumtelnet transcript showing 250 responses
rusers daemon exposedMediumrusers -al output
Legacy R* services open (513/514)Highnmap port state + rpcinfo output
Operator Takeaway: Every username discovered here reduces the brute-force search space for SSH, FTP, and web applications. A list of 8 confirmed usernames is worth hours of cracking time.
